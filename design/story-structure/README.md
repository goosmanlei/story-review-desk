## 自由评论

### 文字

- 可选取正文、标题、人物名称、成长过程与图注中的文字，从浮动入口发表评论。
- 同一评论可覆盖多个文本块；保存每个块的标识、原稿版本、字符区间、准确引用及前后文。
- 图内的可选文字转换为同一图中的精确区域引用，并保留所选文字。
- 评论提交后，原文显示标记；点击标记可查看意见，评论中的定位动作可回到原文。

### 图片与图示

- 每幅图提供“圈选评论”和“评论整图”。
- 圈选支持自由拖动闭合区域；按住 Shift 使用矩形。接近直线的拖动以矩形区域记录，避免留下无面积的选择。
- 保存相对于图像边界的归一化形状、位置、图像标识和所在稿件版本。图像缩放或布局改变时，圈选随同缩放。
- 评论列表支持回到对应原稿和图中位置。氛围图与四张结构图沿用同一套区域评论交互。

### 处理与改稿

- 支持整体意见、文字意见、图中意见、修改意见、标记解决和重新打开。
- 评论随原稿保留；新稿不静默继承旧文字上的字符位置或旧图上的区域。
- “看调整示例”用预置意见演示村人的变化怎样由具体行动推动，并同步调整正文、人物关系图和副线。
- 该预置演示不声称理解用户新写的评论。新评论保持待处理；示例原意见调整后仍需用户复核，不自动解决。
- 正式开发需要 Codex 读取真实意见和原稿上下文，解释对意见的理解、提出调整及影响范围，再交付完整干净的新稿。
- 评论导出包含所有示例稿件的正文、准确意见、图中位置、按稿件保存的 SVG 图示快照，以及氛围图的身份和本地素材引用。独立图片素材需与原 HTML 一并用于实际多模态读取。

## 认可与剧本交接

用户认可的是一个明确版本的完整阅读稿。它的主题、人物塑造、关系、空间、故事线和时间安排共同成为剧本输入；不要求用户把它们重新填写成结构化表单。

未解决意见作为待决问题保留，不自动当成已经落实的要求。改动核心安排时应产生新稿再审阅。HTML 中的“认可这一稿”仅作用于演示，不等于认可页面设计、真实故事方案或任务发布。
