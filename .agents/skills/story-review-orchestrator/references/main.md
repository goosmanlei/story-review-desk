# MainAgent 入口

Main 是当前会话本身，不再创建另一个与用户对话的 Main。使用当前会话稳定 ID 作为 `entryId`；未提供会话 ID 的环境可建立本会话独有的随机标识，在本会话后续调用中保持不变。

## 命令入口

运行 `node review-software/scripts/instance-orchestration.mjs COMMAND --project PROJECT --instance INSTANCE --entry-id ENTRY_ID`。所有路径使用当前项目明确绑定的绝对路径；命令支持 `--input FILE` 或 `--input -` 从标准输入读取 JSON。避免把任务正文、用户回答或凭据插入 shell 命令。需要写 JSON 文件时使用受支持的文件编辑工具，写在项目私有运行目录。

- `attach`：接入 Main 身份，输入 `{entryId,takeover}`。首次接入不派发工作；存在其他有效 Main 时，只有当前用户明确接管才使用 `takeover:true`。
- `status`、`list`、`task`、`events`：查询运行情况、历史与当前任务、结果评价及待决策事项。`task` 输入任务标识，`events` 使用上次游标；不要把事件输出长期写回指引。
- `activate`：以项目当前授权、作用范围及授权来源激活模式；可设置实际可用模型、推理强度及四类并发。安装或历史模式记录不等于本次授权。
- `start`：启动并核对后台就绪；未激活时必须提供明确授权。只有返回实际就绪，才向用户报告模式已启动。
- `submit`：发布 `CREATIVE` 或 `DEVELOP` 任务，参见任务协议。先澄清会实质影响产出的歧义；可由实例事实解决的问题自行查证。
- `decision`：提交用户对指定请求的回答。`scale` 分别调整四类并发；`pause` 停止领取新任务；`resume` 恢复；`stop` 请求在途任务安全收尾。

身份能力由 CLI 保存于实例私有运行目录，Main 调用持续使用同一 `--entry-id`，不得展示、复制到任务正文或提交能力凭据。也可用 `STORY_REVIEW_MAIN_ENTRY_ID` 环境变量传递入口标识。

升级已存在的项目时，先完成软件包及对应 `core-lock` 更新，再运行 `node review-software/scripts/instance-skills.mjs install --project PROJECT` 同步受管副本并回读验证。不得删除或覆盖发生本地修改的 Skill 来绕过安装冲突。

## 协作节奏

开启后先呈现需要用户处理的未决请求，再汇总当前进行中与完成的任务。普通讨论直接回答；有交付目标时将目标、范围、验收标准、精确输入和依赖发给 Schedule。可把一个用户目标拆成相互依赖的创作和开发任务，但不得扩大授权范围。

保持读取事件：活动会话中及时转述关键进展、阻塞与待决策事项；空闲时使用事件等待或运行器支持的监控入口，不用高频循环查询。关闭入口不会关闭后台。接入恢复时以任务账本和实际进程状态为准，不凭旧对话宣称仍在运行。

用户决策请求必须包含具体任务、影响范围和可选择的处理。第三轮质检失败时展示三轮缺陷及已做修正；堵塞时同时展示四类 Worker 的并发、运行／等待数量和建议。额度或工具错误附安全的错误摘要及请求 ID，不能附密钥。

用户未回答时，受影响任务保持等待；无依赖关系的任务可继续。不得将等待时间当成批准。新的用户指令优先调整现有任务，取消或改变输入时由调度器更新任务并保留历史。
