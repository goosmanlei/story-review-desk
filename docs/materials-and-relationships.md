# 素材卡与实体关系

本文供维护制作页面与接口的开发者使用。实体管理用于审阅实体、完整状态和素材方案；素材管理用于审阅真实需求、实际文件及其来源。两个管理页正文只列共用小卡，点击后通过弹窗打开共用实体大卡，与视听制作、镜头制作及叠层弹窗共用评论面板。页面提供准确版本审阅、评论、预览及明确采用；导入、登记文件、修改说明、添加需求及维护关联由后台 CLI／接口完成。

## 页面与评论

大卡左侧保留实体基础信息、直接关系，并在基础信息下以“实体素材／实体状态”两个 Tab 组织唯一素材入口。实体素材列实体级需求与尚未绑定状态的历史原件；实体状态列状态、所选描述版本及该准确版本的素材。实体列表首次进入默认状态 Tab，准确状态／素材链接优先定位其归属；主动切 Tab 恢复各自有效选择。切状态描述版本只在该状态版本内保持原素材或选择第一项，没有素材就留空，不能借实体级需求补位。右侧阅读当前选中的一份素材。没有实体归属的需求显示其剧／集／场／镜等准确制作位置；历史独立素材没有归属时说明缺失，不制造实体。实体管理按类型分组四列小卡，显示当前状态身份数量、去重素材数；素材管理按真实集场分组，区分唯一素材数与展示项数。两个列表底部共用四列基准行分页，口径、来源和全部入口见[管理小卡契约](small-cards.md)。

实体类型和版本位于标题行；当前设计及其适用状态直接阅读，意见绑定准确原文与范围。默认最新实体版本，准确链接和手动选择优先。剧情来源与关联镜头作为导航直接可达；较多来源用选择器定位准确场，避免长按钮墙。关闭上层弹窗恢复选择和阅读位置，迟到响应不得覆盖新选择。

实体图中，同一对稳定对象只画一条连线，旁边直接呈现摘要、关系编号及两端名称编号。不同方面与发展阶段归入这条关系的连贯正文，不增加说明大卡或默认长表。完整正文从摘要的“查看关系原文”打开，准确依据紧邻原文。图内保留正方形视窗、平移和缩放；`config/entity-relationship-layout.json` 的 `primary`／`order` 只控制排列。

单击非当前节点、曲线或摘要，选中这对对象之间的唯一当前关系。端点、曲线与说明同步高亮，切换替换选择，空白或图内 Esc 清除。选择留在本次大卡上下文，不写业务数据或递归加载。双击或 Enter／空格打开关联实体；S 选择节点关系。说明和曲线支持 Enter／空格选择，正文圈选、评论及来源按钮保留原能力。拖动超过阈值才平移，不误触点击。

标题同行提供“展示完整关系图”“原始大小”“扩大”“缩小”。完整图适配全部节点／说明／路径，原始大小恢复 100%，连续缩放范围为适配所需最小比例至 400%；边界显示比例及禁用控件。文字、线条、点击区域和评论锚点一起缩放；缩放与窗口变化保持逻辑查看中心和选择。图内 +／−、0、F 分别缩放、还原、完整图，方向键平移。叠层关闭后返回原图上下文。模态框的文字评论浮动入口放在当前叠层内，避免浏览器将其设为不可点击。

统一关系正文按不可变修订保存，准确参考与意见始终读取当时修订。迁移前已执行的旧说明清理仍有效：被清理的旧正文只显示清理提示，不用新说明补造；原评论的引文和事件保持。新关系不再执行旧模型的 latest-only 说明删除。采用边、真实调用、对象版本及父子归属仍守原契约。

桌面大卡采用左右布局，素材阅读列有独立滚动；窄屏改为上下单列，素材内容完整展开。图像在预览框内按原比例显示完整图幅，圈选层只覆盖实际图幅；多个原件的组成 ID 即使都叫 `original`，拖选仍绑定实际点击的图和准确修订。无原件时只为该需求显示对应媒体类型的占位；已有声音直接显示波形播放器，不使用人物封面。正文与弹窗复用相同媒体、生成信息、版本控件和评论表面，不能维护两套简化卡。

共用素材卡按“素材名称与版本／候选 → 结果或未生成占位 → 生成方案”阅读。已有候选直接呈现该原件实际 CALL（真实调用记录）的模型、参数、有序输入和完整 Prompt；没有结果则读取所选版本保存的方案。计划参考与实际输入分别标明，输入列表保留准确版本、组成、裁切和时间范围。参考按钮及 Prompt 中的 @图片／@音频链接共享该准确方案固定的关系摘要；悬停、聚焦或向下键可读，Esc 关闭并返回焦点，原点击仍打开准确素材。移入摘要可继续阅读，窄屏内约束宽度；切版、候选、组成或关闭卡片时过期结果不得覆盖当前上下文。摘要不是正文字符锚点，评论须打开准确关系原文或圈选原 Prompt。缺历史 CALL 时明确说明缺失，只展示可证的原保存方案，不能借当前方案补写来历。原意见与准确采用记录可回查；浏览不会改变输入选择。原件、预览、回执组成仍可切换；非媒体文件提供下载。

通用审阅标准只从准确需求的原字段读取，在相应审阅操作旁以“？”提供 hover、键盘聚焦和点击固定阅读；不复制另一套标准，也不作为默认正文。具体作品约束留在准确描述或完整 Prompt。生成时自检和确定性检查仍由准备流程承担，不冒充人工判断。

原件的真实意见直接显示作者、原时间、原话和范围；历史导入通过评论事件保存来源，不建立独立决定对象。意见仅适用于原准确内容，相反意见并列；原锚点不迁到新版本。

实际输入与旧备选的原件引用保留准确版本和组成，原意见从同一评论入口读取。历史导入保留来源、原主体、原发生时间和范围，不显示为今天的新发言；关闭讨论不代表质量通过。

共用素材大卡不再默认列出“已有形象”“沿用方案”和其他用途关系。它们仍是历史备选或下游依赖，不是所选需求的生成候选；后台查询、引用校验与旧评论原文继续保留。移除展示不构成删除关系、原件、调用或意见的授权。真实输入继续由当前准确生成方案直接打开，点击参考不选用、不扩展旧意见范围、不重挂状态。

共用卡的用途读取携带同一记录的对象与修订，优先读取卡片显示的准确素材要求，包括冻结版本保存的原需求。冻结 `plan-v1` 的活动方案为空时，仍沿 `definition_records.requirement` 读取，不能把需求对象与候选修订混配，也不能以当前需求填旧卡。没有保存要求时，使用所选候选自身的完整引用；既无要求又无候选则不补造用途。准确关系为空沿用空态，错配或已删除目标继续按原契约拒绝；候选评论始终使用候选自己的引用。

实体、素材和镜头入口复用同一准确原件的评论。保存、编辑、关闭和重开沿原评论接口；草稿按准确对象、修订和锚点保持，迟到响应不得覆盖另一张卡。实际修订回应沿 [评论回查](comment-review.md) 返回原文与新版本。

实际调用的模型、参数和提示词使用共用文字圈选；图像和音视频沿用区域／时间锚点。素材管理汇总该素材方案版本、准确调用和关联方案的评论，定位调用评论后刷新仍保留素材卡上下文。旧素材评论打开原文件及原始生成记录。所有评论仍绑定准确修订。

定位旧调用、方案和自检文字意见时，沿原对象、原修订、原块和原偏移读取承载该意见的正文，不将意见迁入相似的新句。当前编排未呈现的原句通过“评论原文”直接读取，必要的原方案和调用参考沿准确历史获取。原件只有历史状态关联时也不换当前状态头；历史意见仍在汇总面板。缺记录和文件组成继续明确说明。

素材版本与候选使用各自可横向滚动、右对齐的两行按钮；真实序号由左到右从旧到新，最新在右，DOM 和键盘顺序一致。初始选中项自动滚入可见范围，溢出时可横向浏览全部选项。普通列表或素材小卡进入时，默认选择版号最大的、有真实候选的版本；全部没有候选才选最新版本。候选行仅显示该版本的“候选N”，默认最新登记候选，与既有采用无关。手动选择未生成版本只显示该版方案，候选行不出现。准确链接、历史评论和明确选择优先；它们必须保持指定对象、修订、版本和候选，匹配失败明确报错。浏览选择不写采用记录。采用组成、区域或时间范围只作用于对应原件组成。

各入口实体／素材小卡打开完整大卡弹窗，各类评论沿用正文能力。唯一例外是大卡左侧底部素材列表，只切换同卡右侧素材，保留实体、状态、位置和草稿。关闭、Esc 或浏览器后退恢复外层对象、草稿及触发焦点，并停止弹窗媒体；读取未完成就关闭或切页时，旧响应不得替换外层审阅目标，叠层读取也不能覆盖上层。素材版本往返按准确修订、素材标识及方案版本保存本页草稿上下文，不能把一个版本的锚点带到另一版本。管理页筛选和分页不随弹窗打开、素材切换或评论定位重置。

“参考输入”的实体、状态与素材方案进入共用完整卡；图像、声音和视频引用仍使用准确组成、裁切和时间片段的参考窗，评论绑定引用对象的准确修订与文件。“剧情依据”和“原方案”保留独立的准确历史阅读：旧方案支持原文字评论；剧情依据默认读原引用选段，存在省略时提供同修订全场补读。它们不提供素材维护。无产出的需求不自动选最新结果。剧情来源使用 `/api/production/source` 校验准确分集、场和正文块。参考图可点击或用 Enter／空格放大。

选段的“读完整场”复用 `full_scene=1`，始终沿原对象、不可变修订和准确场读取；全文高亮仅标原引用，“返回选段”恢复选段阅读位置，关闭仍回原用途或状态卡。补读不扩大引用、不切换评论对象或提交草稿。已有全文入口及完整引用不追加重复控件。`scene_context` 仅提供全场段数与省略位置/段数，选段请求不预载全文；场内顺序沿准确场的 `block_ids`。只有正文块时，须由同一修订中唯一包含全部引用块的场确认上下文；不唯一时仅读原选段并说明不能补读。历史正文、场或块失效时拒绝替换最新版。当前全文失败保留选段并在读取动作旁说明限制；关闭后迟到的成功或失败不得恢复旧弹窗或抢另一来源焦点。

剧情依据、参考输入、原方案、原图和完整大卡复用 `openReviewDialog` 的标题、关闭按钮与历史处理。Esc 只关闭最上层弹窗；评论输入框内的 Esc 仍按共用编辑器规则取消本次草稿。关闭按钮不得留下额外同页历史项，弹窗内刷新实体或切版本也必须保留弹窗历史标记。素材卡只展示帮助判断的缺项，执行日志保留在后台。

## 视听制作

顶部按集切换，左侧导航场与镜，正文连续阅读所选场的全部镜头。场面共同条件先读一次，动作、原词和独有专业选择按镜头顺序直接呈现；准确参考按具体用途在同场组织，保留每镜消费者。全场成果与制作方案另有明确导航，未生成需求不作为人工逐项待办。素材须有准确需求、计划参考、实际输入或采用关系，不因人物入画而推定每镜使用。

动作正文与专业选择按准确原文编排，契约见 [视听制作](production-breakdown.md)。参考标记打开准确输入，素材小卡使用共用大卡。场镜历史按准确父修订读取，移场不改写旧归属。宽屏目录与正文分别滚动；窄屏上下排列，正文自然延伸。

## 素材条目与生成状态

素材管理以每个实际需求为一个条目，结果和方案版本在该条目内选择；同一需求的多个结果、调用与修订不重复计数。“生成结果（含历史版本）”筛选中的“有结果”，要求至少一个版本存在非占位、含受管 original 组成的真实结果；仅有方案、失败调用或占位属于“无结果”。这里表示曾有真实产出，正在准备的新版本仍可没有结果；筛选保留有无结果口径；小卡只显示总版本数和总候选数，准确版本大卡继续显示该版本的“已生成／未生成”。没有有效需求关联的历史素材保留独立条目，原对象／修订链接继续可读，不制造需求。

生成结果与图像、声音、视频、工程、说明文件等分类可以组合搜索和清除。类别集合从完整可浏览条目得到；没有内容的类别不显示，搜索或其他筛选为零不移除已有类别。各选项数量按同一条目口径，在计算该维度数量时保留其他筛选。调用、原评论和明确镜头采用继续通过原详情、关联用途、CLI 与历史读取；意见不代替准确选择。

实体列表中的媒体数量采用相同条目口径：同一需求的多个候选、组成和修订不重复计数；同一条目对同一实体只计一次。有真实产出不表示已被镜头采用或已经就绪。是否适合当前用途须结合准确输入和实际声画判断。

## 只读页面接口

素材条目的 `generation_scope` 表示生成状态的统计范围：需求条目为 `history`，包含其历史候选；独立实际素材为 `exact`，只表示该条目的准确记录。小卡通过全部真实版本／候选计数表达登记量，实体大卡内已选版本仍只显示该版本是否生成。同一素材的别名合并保留任一有效原件结果，不因别名排序漏掉生成状态或预览。

打开“选择素材版本”时，若调用方没有给出明确候选数组，才读取完整素材清单并按媒体类型选择；明确的空候选数组仍为空。选择对象后另读准确历史，采用继续提交所选修订和组成文件，不因当前列表刷新替换历史引用。载入失败保留输入并禁止错误提交，关闭后可重新打开读取。

页面投影是把已有对象、修订、关系和方案版本组织成当前页面所需的读取结果。实现位于 `review_desk/ui_projection.py` 与 `production_breakdown.py`，不建立第二套存储，不生成媒体、不写业务数据、不迁移 Schema 或改变导出协议。

| GET 接口 | 页面用途与准确性边界 |
| --- | --- |
| `/api/production/index?view=settings` | 返回实体、状态、关联说明，以及实体的媒体条目数和完整状态数。`object_id` 可保留旧准确链接的入口对象。 |
| `/api/production/materials` | 按需求及历史独立素材返回分页条目、生成状态、媒体／集／场筛选计数；`focus` 可定位准确链接所属条目，筛选外目标单独列出，不计入筛选结果总数。 |
| `/api/production/card?object_id=ID[&revision_id=SHA]` | 聚合准确详情、实体／状态、制作位置及采用上下文，供正文和完整大卡弹窗共同渲染。 |
| `/api/production/scene?object_id=ID[&revision_id=SHA][&shot_revision=SHA]` | 返回准确场、共用素材及逐镜上下文；指定镜头必须属于该场的准确修订。 |
| `/api/production/breakdown?episode=ID` | 返回集场目录及所选集的制作入口。 |

`/api/production/materials?grouped=1` 返回全部筛选素材、真实分组与唯一／展示计数，由共用前台分页按组内四列行切页；原 offset／limit 接口兼容。实体索引增加 `entity_state_counts` 和带证据的 `entity_locations`。两个管理投影的 `management_episodes` 使用已有分集的权威编号，独立于视听制作输入锁的导航范围。`/api/production/card` 可带准确 `entity_id`，校验目标属于该实体。

这些聚合读取在同一读取范围内完成；版本、候选和引用仍由原契约校验。已有 `/api/production` 精确详情、实体审阅、来源和文件接口继续兼容；列表中的 `material_assets` 仍记录既有需求／真实结果对象关联，不新建关系。精确历史链接的参数 `material_id`、`material_version`、兼容旧轮次的 `material_round` 及 `material_target` 由共同卡片验证，不能忽略错误参数后退到当前版本。

素材版本、候选、原始输入、块评论及旧轮次迁移契约见 [方案版本与候选](material-versions.md)。原件、调用、不可变修订和准确采用继续保留；不能以旧数据库修订次数推断制作轮次。

## 关系契约

实体、状态、素材需求／真实素材和镜头等业务对象，共用 `RELATION`、`relation_type: business`。两端使用稳定对象 ID；无序对象对唯一确定关系 ID，不因反写、方向、方面、阶段或撤回重建而变。内容只有一份摘要和连贯正文，禁止另建类型或子关系保存同对多条。

```json
{
  "object_id": "由 business_relations.identity([a,b]) 计算", "kind": "RELATION", "expected_version": 0,
  "payload": {
    "format": "production-relation-v1", "relation_type": "business",
    "title": "人物与住所", "blocks": [{"id": "relationship", "text": "该阶段人物暂住此处；迁居后的联系仍由原剧情依据说明。"}],
    "endpoints": ["person", "place"], "direction": "related",
    "summary": "该阶段暂住此处。", "sources": [], "contexts": [], "status": "active"
  }
}
```

上例是结构示意；实际写入须先读取真实端点和来源，由身份函数计算 ID。导入会排序端点并同步翻转方向，拒绝自关系、缺失端点、错误身份及过期版本。`related` 表示相关；`forward` 表示第二端依赖第一端，`reverse` 反之。编号如 `R-EN012->EN055`、`R-EN012-EN055`、`R-M012<-EN055`。端点顺序稳定，正反写解析同一身份。人物的行为方向不转换为制作依赖；跨阶段依赖不能由一个箭头表达时使用相关。`sources` 保存准确依据，`contexts` 保存适用阶段的准确修订；撤回追加 `withdrawn` 修订，不删除历史。

写入仍用 `POST /api/production/import` 或 `production-import FILE`，携带准确 `expected_version`／`expected_heads`，可先 `--validate-only`。`GET /api/production/relations` 或 `production-relations` 按端点／编号查询；按需求及修订查询时只返回该版固定的输入关系。旧 RL／MR 和对象 ID 映射到统一身份，原修订保留只读；切换后禁止向旧 `RELATION/entity`、`MATERIAL_RELATION`、`RELATION/applicability` 追加，当前列表也不混入别名。

生成输入通过准确 `relation:{object_id,revision_id}` 固定本对关系。`semantics`、`necessity`、`group`、`route`、`condition`、启用状态、候选、组成、裁切及时间范围均留在具体方案。普通关联不自动上传；多个组成共用关系身份，但各自保留范围。只检查本次已选路线的缺项与循环，不按图中所有箭头计算执行依赖。关系改写不偷换冻结输入，不改变原评论、准确选择或真实 CALL。

受管媒体方法冻结完整关系修订、当前作品阶段和准确参考，作者将适用约束融入完整 Prompt；摘要仅帮助阅读，不代替方法输入。旧执行未记录的依据保持未知。关系原文意见仍绑定准确关系修订与实际文字，旧意见不迁到新关系、原件或相似句子。

## 原始生成记录与兼容

素材详情把方案声明的直接参考留在对应准确生成方案。共用大卡只列其有序输入，不展示旧备选或下游用途列表；统一关系承载当前事实，旧关系与准确意见保留只读历史入口。历史方案只读已保存输入，不用当前比较补造旧来历。

仅有实体、状态等逻辑输入的真实调用显示“文字依据”，仍可打开准确旧版本；方案引用、已指定原件及真实调用分别按实际记录表达。关系意见绑定原关系、修订和文字锚点，旧意见保留原文；不迁入原图或其他备选。无图占位紧凑显示未生成，有图继续完整查看、放大、圈选和下载。

ASSET 的 `production` 是实际 CALL 的准确修订。读取素材时返回 `review_context: {call, requirements, inputs}` 和按准确素材修订索引的 `review_contexts`。后者覆盖该素材关联的各轮全部候选，包括同版中其他素材身份的原件；从任一候选进入，实际生成信息都属于当前显示的原件。实体媒体条目也返回这一上下文。即使 CALL 后来登记完成、当前方案改写，也不替换原输入。

已有候选的完整卡先展示原件，再直接读取该原件真实 CALL 的参数、输入和完整 Prompt，无需展开历史按钮。准确记录、执行包与原评论读取路径继续保留。缺调用明确显示历史依据缺口；准确编排失败不能借最新版填充。生成时自检、人工判断、素材采用与镜头放行各守原义。

CALL 投影 `@review/call/model`、`@review/call/parameters`、`@review/call/prompt` 为可评论字段。参数文本由服务端产生；参数中与主提示词完全相同的 `prompt` 只展示一次，原数据不改动。既有正文与生成方案评论锚点保留。

生成方案不再要求或展示 `tool`，执行包也不指定工具。执行者核对平台、额度和接口后选择工具，并在真实 CALL 的 `tool` 中记录；提交后的工具仍不可改写。旧方案中的工具字段保留历史，不能作为新的业务审阅前提。

旧审批对象的真实意见迁入普通评论，纯状态循环删除，冻结调用保留原正文并以最小退役凭据解释原引用。旧端点与旧完整包不能重新写入这些对象，见 [生成准备](generation-preparation.md)。

关系来源可增加图内内容，但不改变正方形视窗高度；平移和滚动可到达全部按钮。历史局部状态与已撤回状态仍按原唯一实体归属可读，不进入当前生成准备范围。共享媒体没有覆盖当前状态时，显示其实际所属实体与状态，不能据此扩大当前实体的采用范围；实体或状态的历史修订继续只读。

## 验证与恢复

`test_material_relationships.py` 验证准确评论、素材采用隔离、原调用评论和导出恢复；`material_review.test.cjs` 验证准确方案与候选匹配、一材多用和调用参数投影。`test_ui_projection.py` 验证需求计数、无副作用读取、准确场镜归属及历史引用；`ui_unification_compatibility.test.cjs`、`ui_unification_requirements.test.cjs` 与 `production_image_region.test.cjs` 覆盖共用卡片、草稿、迟到读取、历史与图像手势上下文。测试几何和事件处理不能替代实际浏览器拖选、滚动与窄屏检查。

完整素材模型的 Schema 12 导出同时保留统一关系身份、旧别名及迁移幂等回执，以及编号分配、候选序号、评论编号、关系清理证明和原文引用保留资格；其他身份、调用、文件、评论事件与依赖保留。完成统一关系切换后，仅用支持 Schema 12 的读取器和当前完整导出恢复，不回灌旧数据库或旧完整说明。可选关系展示配置进入校验清单并恢复到 config/。实例实际计划、归属清单、浏览器证据及正式操作由故事仓库保存。

## 验证入口

`python3 -m unittest discover -s tests -v` 与 `node --test tests/*.test.cjs` 覆盖准确生成信息、历史定位、状态归属、旧说明清理冲突／幂等／未来写入、编号与评论的导出恢复。隔离实例另外实测图内平移、节点打开、来源、版本与候选切换、评论及弹窗返回；这些交互检查不代表媒体创作质量已通过审阅。

## 已清理的历史独立状态

实例可按当前实体、当前版本的完整状态范围审计独立状态对象。批准清单必须包含实体头、对象与全部准确修订、传入引用和评论锚点哈希；打开旧实体版本不能改变清单口径。`state_cleanup.apply` 在同一事务核对全部输入，替换目标正文、移除其冗余状态记录及出边，并可同步删除无用途的归档内容节点；输入冲突整批回滚，重复执行零增量。

清理后不再存在这些对象的 `STATE` 正文。外键及准确历史索引保留 `DELETED_STATE` 身份载体和 `state-cleanup-receipt-v1` 删除凭据，仅包含身份、原哈希、所属实体与原因；不保存旧状态块、维度或来源正文。读取准确历史目标显示“目标已清理”，保留原引用来源，绝不跳到最新状态。真实调用、素材、评论引文、采用及其他对象历史不删除，不声称等价映射。

Schema 9 导出同时携带 `state_cleanup_receipts`、`state_cleanup_preserved` 和 `state_cleanup_comments`。恢复须使用支持删除凭据的新读取器；原不可变对象及已有评论只允许以登记的精确哈希恢复，新写入不得重建已删除对象或增加对它的引用。实例`state_cleanup_policy`按删除身份拒绝把旧导出恢复到空库。只从清理后的导出和批准候选向前恢复，不回滚旧状态库；既有 Git 历史不改写。实例的准确清单、受影响引用和发布／恢复步骤归各实例交付包。
