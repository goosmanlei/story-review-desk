# 素材卡与实体关系

本文供维护制作页面与接口的开发者使用。制作设定用于审阅实体、完整状态和素材方案；素材管理用于审阅真实需求、实际文件及其来源。实体管理、素材管理正文，以及制作拆解／镜头制作打开的“实体与素材”弹窗，使用同一张大卡和同一评论面板。页面提供采纳／取消、准确版本审阅、评论、预览及明确采用；导入、登记文件、修改说明、添加需求及维护关联由后台 CLI／接口完成。

## 页面与评论

大卡左侧保留实体基础信息、直接关系、完整状态和素材小卡，右侧只展开当前选中的一份素材。没有实体归属的需求显示其剧／集／场／镜等准确制作位置；历史独立素材没有归属时说明缺失，不制造实体。左侧实体列表按类型分组，小卡按媒体类型显示素材条目数；这些数量来自需求及无需求关联的历史素材，不是数据库修订数或文件组成数。

“关系”展示全剧直接关系，主要关系靠近中心并先排列，其他关系向外延伸；所有关系均可滚动查看。端点只说明相关实体，不跳转。连线文字使用统一评论提示，选词后直接评论原关系修订。版本下拉在有历史时就地出现，适用集场在当前页弹窗查看准确正文。实例的 `config/entity-relationship-layout.json` 按实体列出 `primary` 与 `order` 的关系 ID；这是展示配置，不改变关系事实或采纳范围。

桌面大卡采用左右布局，素材阅读列有独立滚动；窄屏改为上下单列，素材内容完整展开。图像在预览框内按原比例显示完整图幅，圈选层只覆盖实际图幅；多个原件的组成 ID 即使都叫 `original`，拖选仍绑定实际点击的图和准确修订。无原件时只为该需求显示对应媒体类型的占位；已有声音直接显示波形播放器，不使用人物封面。正文与弹窗复用相同媒体、生成信息、版本控件和评论表面，不能维护两套简化卡。

卡片按所选方案版本和候选显示一份生成内容：尚无结果时显示待执行方案；已有原件时显示该结果真实调用的模型、参数、提示词与准确参考。参数标题包含模型名，有效参考输入位于提示词之前。需求正文、描述和检查要点另行保留；“查看原方案”打开准确历史方案，已有方案评论也会定位到该弹窗。真实调用缺失时直接说明无法还原，不以方案补写。切换素材历史时保留原卡片及版本下拉，不给旧素材补写当前需求。版本状态由下拉本身表达。原件、预览、回执等组成可切换；非媒体文件仅显示下载入口，不创建音频播放器。

实际调用的模型、参数和提示词使用共用文字圈选；图像和音视频沿用区域／时间锚点。素材管理汇总该素材方案版本、准确调用和关联方案的评论，定位调用评论后刷新仍保留素材卡上下文。旧素材评论打开原文件及原始生成记录。所有评论仍绑定准确修订。

制作设定与素材管理的准确链接直接选中指定候选，每次只展示一份原件；同版其他候选用候选下拉查看。没有明确候选时，优先显示本版中已明确采用的原件，否则使用已有候选选择规则。采用所登记的组成、区域或时间范围只作用于对应原件组成；用户切到其他组成时不套用原范围。切换同时更新原件组成、实际生成记录、用途和审阅目标，保留所有旧候选与轮次。版本、素材标识或候选不匹配时明确报错，不替换成最新结果；浏览选择本身不写采纳或采用记录。

制作拆解中的素材小卡打开完整大卡弹窗，实体采纳和各类评论沿用正文能力。关闭、Esc 或浏览器后退恢复外层对象、草稿及触发焦点，并停止弹窗媒体；读取未完成就关闭或切页时，旧响应不得替换外层审阅目标。素材版本往返按准确修订、素材标识及方案版本保存本页草稿上下文，不能把一个版本的锚点带到另一版本。

“参考输入”“剧情依据”和“原方案”是独立的准确引用弹窗，不等同于完整大卡。“参考输入”可查看原图、声音／视频片段、设定或生成方案；其中音视频评论绑定被引用对象的准确修订、文件与时间范围，沿用共用面板。“原方案”支持定位及评论历史方案文字；剧情依据只展示所引正文。此类弹窗不提供实体采纳或素材内容维护。尚未产出的需求只显示缺失与原方案，不自动选取最新结果。关系的剧情依据和集场来源使用 `/api/production/source` 读取准确分集修订、场次与正文块，不追随当前剧本。参考图可点击或用 Enter／空格打开完整原图，再返回参考弹窗。

剧情依据、参考输入、原方案、原图和完整大卡复用 `openReviewDialog` 的标题、关闭按钮与历史处理。Esc 只关闭最上层弹窗；评论输入框内的 Esc 仍按共用编辑器规则取消本次草稿。关闭按钮不得留下额外同页历史项，弹窗内刷新实体或切版本也必须保留弹窗历史标记。素材卡只展示帮助判断的缺项，执行日志保留在后台。

## 制作拆解与镜头制作

顶部按集切换，左侧列本集场次，正文一次展示所选场的全部镜头。场说明在顶部，共用素材不在场顶部重复列出；每个镜头独立占一行，左侧为镜头内容，右侧只列本镜明确关联的素材，不使用一个随选中镜头变化的公共右栏。归属过滤保留剧、集、场、镜四个层级。素材须有准确需求、计划参考、实际输入或采用关联，不能因上级归属或某状态在本场出场，就推定每镜使用。

制作拆解显示镜头设计；镜头制作沿用同一集场和逐镜布局，显示本镜视频需求。已有候选展示该候选真实调用的输入、参数和提示词；未生成时展示准确方案及待补输入。提示词中的参考标识链接到准确输入，素材小卡打开同一大卡。场与镜的历史链接按准确父修订读取，镜头调整归属后仍不得把旧镜头挂到当前场次。宽屏目录与正文分别滚动；窄屏逐行上下排列，场正文自然延伸，不受旧的高度上限裁切或被页脚覆盖。

## 素材条目与生成状态

素材管理以每个实际需求为一个条目，结果和方案版本在该条目内选择；同一需求的多个结果、调用与修订不重复计数。“生成结果（含历史版本）”筛选中的“有结果”，要求至少一个版本存在非占位、含受管 original 组成的真实结果；仅有方案、失败调用或占位属于“无结果”。这里表示曾有真实产出，正在准备的新版本仍可没有结果；列表使用“有生成结果／无生成结果”，准确版本大卡继续显示该版本的“已生成／未生成”。没有有效需求关联的历史素材保留独立条目，原对象／修订链接继续可读，不制造需求。

生成结果与图像、声音、视频、工程、说明文件等分类可以组合搜索和清除。类别集合从完整可浏览条目得到；没有内容的类别不显示，搜索或其他筛选为零不移除已有类别。各选项数量按同一条目口径，在计算该维度数量时保留其他筛选。调用、审阅判断和明确镜头采用继续通过原详情、关联用途、CLI 与历史读取；内容认可仍不等于镜头采用。

实体列表中的媒体数量采用相同条目口径：同一需求的多个候选、组成和修订不重复计数；同一条目对同一实体只计一次。有真实产出不表示内容已采纳、被镜头采用或已经就绪。实体采纳筛选依据当前准确范围的有效采纳，不凭任意历史采纳记录判定。

## 只读页面接口

素材条目的 `generation_scope` 表示生成状态的统计范围：需求条目为 `history`，包含其历史候选；独立实际素材为 `exact`，只表示该条目的准确记录。制作拆解和镜头素材小卡据此注明“含历史版本”，实体大卡内已选版本仍只显示该版本是否生成。同一素材的别名合并保留任一有效原件结果，不因别名排序漏掉生成状态或预览。

组合与历史的目录只包含检查和组合记录。打开“选择素材版本”时，若调用方没有给出明确候选数组，才读取完整素材清单并按媒体类型选择；明确的空候选数组仍为空。选择对象后另读准确历史，采用继续提交所选修订和组成文件，不因当前列表刷新替换历史引用。载入失败保留输入并禁止错误提交，关闭后可重新打开读取。

页面投影是把已有对象、修订、关系和方案版本组织成当前页面所需的读取结果。实现位于 `review_desk/ui_projection.py` 与 `production_breakdown.py`，不建立第二套存储，不生成媒体、不写业务数据、不迁移 Schema 或改变导出协议。

| GET 接口 | 页面用途与准确性边界 |
| --- | --- |
| `/api/production/index?view=settings` | 返回实体、状态、关联说明，以及实体的媒体条目数和当前采纳状态；`view=history` 保留组合与历史入口。`object_id` 可保留旧准确链接的入口对象。 |
| `/api/production/materials` | 按需求及历史独立素材返回分页条目、生成状态、媒体／集／场筛选计数；`focus` 可定位准确链接所属条目，筛选外目标单独列出，不计入筛选结果总数。 |
| `/api/production/card?object_id=ID[&revision_id=SHA]` | 聚合准确详情、实体／状态、制作位置及采用上下文，供正文和完整大卡弹窗共同渲染。 |
| `/api/production/scene?object_id=ID[&revision_id=SHA][&shot_revision=SHA]` | 返回准确场、共用素材及逐镜上下文；指定镜头必须属于该场的准确修订。 |
| `/api/production/breakdown?episode=ID` | 返回集场目录及所选集的制作入口。 |

这些聚合读取在同一读取范围内完成；版本、候选和引用仍由原契约校验。已有 `/api/production` 精确详情、实体审阅、来源和文件接口继续兼容；列表中的 `material_assets` 仍记录既有需求／真实结果对象关联，不新建关系。精确历史链接的参数 `material_id`、`material_version`、兼容旧轮次的 `material_round` 及 `material_target` 由共同卡片验证，不能忽略错误参数后退到当前版本。

素材版本、候选、原始输入、块评论及旧轮次迁移契约见 [方案版本与候选](material-versions.md)。原件、调用、不可变修订和准确采用继续保留；不能以旧数据库修订次数推断制作轮次。

## 关系契约

沿用 RELATION，增加 `relation_type: entity`，与已有 `adoption` 采用关系分开校验和查询。无新表。示例：

```json
{
  "object_id": "relationship-person-place", "kind": "RELATION", "expected_version": 0,
  "payload": {
    "format": "production-relation-v1", "relation_type": "entity",
    "title": "人物 · 暂住 · 住所",
    "blocks": [{"id": "relationship", "text": "该阶段人物暂住此处。"}],
    "entities": [{"object_id": "person", "revision_id": "准确修订"}, {"object_id": "place", "revision_id": "准确修订"}],
    "label": "暂住", "direction": "forward", "category": "spatial", "basis": "script",
    "sources": [{"object_id": "episode", "revision_id": "准确修订", "scene_id": "s001", "block_ids": ["b001"]}],
    "applies_to": [{"object_id": "episode", "revision_id": "准确修订", "scene_id": "s001", "block_ids": ["b001"]}],
    "status": "active"
  }
}
```

两个端点必须是不同的准确 ENTITY 修订；方向为 `forward` 或 `mutual`。类型为人物 `personal`、空间 `spatial`、归属 `ownership`、使用 `use`、演唱／演出 `performance`。依据区分剧本事实 `script` 与制作选择 `production`；必须保留准确来源。`applies_to` 标明已核实的剧情适用范围，稳定身份关系可为空；不能把一次使用推断成永久持有。撤回用 `status: withdrawn` 新修订，原评论和历史采纳保留。

写入使用既有 `POST /api/production/import` 或 `production-import FILE`，携带 `expected_version` 与 `expected_heads`；可 `--validate-only` 预演。读取沿用 `/api/production?object_id=ID[&revision_id=SHA]`／`production-get --object ID [--revision SHA]`，不增加另一套存储。实体审阅响应增加 `relationships`、`related_entities`、`materialContexts`；准确关系修订纳入采纳的 `scope.relationships`。新增、撤回或改变关系后，需要重新认可生成准备；已有采纳仍可显式取消。

## 原始生成记录与兼容

ASSET 的 `production` 是实际 CALL 的准确修订。读取素材时返回 `review_context: {call, requirements, inputs}` 和按准确素材修订索引的 `review_contexts`。后者覆盖该素材关联的各轮全部候选，包括同版中其他素材身份的原件；从任一候选进入，实际生成信息都属于当前显示的原件。实体媒体条目也返回这一上下文。即使 CALL 后来登记完成、当前方案改写，也不替换原输入。

CALL 投影 `@review/call/model`、`@review/call/parameters`、`@review/call/prompt` 为可评论字段。参数文本由服务端产生；参数中与主提示词完全相同的 `prompt` 只展示一次，原数据不改动。既有正文与生成方案评论锚点保留。

生成方案不再要求或展示 `tool`，执行包也不指定工具。执行者核对平台、额度和接口后选择工具，并在真实 CALL 的 `tool` 中记录；提交后的工具仍不可改写。旧方案中的工具字段保留历史，不能作为新的业务审阅前提。

旧 `entity-current-v1` 采纳不转换为生成许可。用户可取消它，即使当前描述／方案未完善：实体响应给出 `can_revoke`、`revoke_target` 和规范决策的 `decision_version`；取消请求必须带准确 `decision_ref`。规范决策追加 revoked 修订，指回旧采纳，旧对象不修改。后续读取优先规范决策，不能使旧采纳复活。内容变化后的新模型采纳也可取消，取消不要求当前方案完整。

当前实体可以采纳、取消并再次采纳，首次采纳或旧记录之后新增素材也适用。描述或方案缺项、前置方案换版时，响应使用 `acceptance_mode: content`，`decision_scope` 锁定当前实体、关系、完整状态、需求和递归依赖的准确修订；保存为 `entity-content-v1`，存在前一决定时以 `previous_decision` 串接历史。`content_accepted` 表示内容已采纳，`accepted` 仍为空，生成检查及执行包继续阻断。方案完善后须明确采纳完整方案，不自动把内容认可升级为生成许可。

旧 `entity/states/media` 内容认可及其取消链继续可读、可取消；旧客户端仅在原范围仍准确匹配时可重采纳。当前页面采纳最新内容，不要求曾有旧认可，也不依赖关联素材列表保持不变。历史阅读始终只读，重复／过期版本或内容范围请求拒绝追加，取消与重采纳均保存历史。

多个剧情来源按钮按实际数量留足关系图高度，不裁切证据入口。更改筛选时按照新结果选择可见实体；仍在结果中的准确选择继续保留。快速切筛选、切页或打开后关闭弹窗时，迟到读取不得恢复已离开的实体或覆盖新上下文。

## 验证与恢复

`test_material_relationships.py` 验证旧采纳取消、并发拒绝、关系变化后的重新认可、素材采用隔离、原调用评论和导出恢复；`material_review.test.cjs` 验证准确方案与候选匹配、一材多用和调用参数投影。`test_ui_projection.py` 验证需求计数、无副作用读取、准确场镜归属及历史引用；`ui_unification_compatibility.test.cjs`、`ui_unification_requirements.test.cjs` 与 `production_image_region.test.cjs` 覆盖共用卡片、草稿、迟到读取、历史与图像手势上下文。测试几何和事件处理不能替代实际浏览器拖选、滚动与窄屏检查。

Schema 5 导出保留所有关系、决策、调用、文件及评论事件；可选关系展示配置作为 `entity-relationship-layout.json` 进入校验清单，空实例恢复写回 `config/`，含此文件的导出须使用支持它的系统版本；恢复须使用支持本契约的系统。实例的实际批次、浏览器操作和空库恢复证据由故事仓库保存。接口测试或播放器推进不代表创作接受或实际听辨。

## 验证入口

`python3 -m unittest discover -s tests -v` 与 `node --test tests/*.test.cjs` 覆盖准确生成信息、旧版卡片定位、可取消采纳、描述型状态、显式需求清理的评论／历史依赖保护与事务回滚，以及关系显示配置的导出恢复。页面在隔离实例验证关系不跳转、直接圈选评论、素材方案版本往返和参考弹窗关闭后的草稿与阅读位置；这些交互检查不代表媒体创作质量已通过审阅。
