# VPS 发布器本机验收

验证日期：2026-09-11。软件工作基线：`ebfb520c7f0493dabf66cc8fc6b1c94be0725021`。下表严格区分实现、真实本机观察和未观察项；本记录不是生产部署证明。

## 已观察

| 项目 | 本机证据 |
| --- | --- |
| 完整包 | 软件清单、NDJSON PostgreSQL、登记 PNG、两份 Linux amd64 镜像；逐文件 SHA／大小、数据库语义、媒体退役协议与四遍恢复校验通过 |
| 连续发布 | A `5e3e7029…` → B `8e6f01b6…` → C `f73086e2…`；每版制造 REMOTE_DIRT，下一版恢复各自本地基线；C 的 backup 为 B |
| 干净回滚 | C → B，新 runtimeEpoch，业务身份和冻结中文／逻辑 URL 字节保持，远端配置草稿未回灌 |
| 浏览器 | 独立 loopback TLS Nginx，经 Basic Auth；六个工作区深链与刷新、业务配置草稿写入、图片 Range、合成 WAV／MP4 SHA 与 Range、浏览器媒体解码及下载通过；同源资源逃逸为零 |
| 访问控制 | 页面／API／媒体／静态／SSE 未认证 401；错误 Origin 403；直接 socket 伪造代理身份 403；旧页面写入 409 并显示刷新拦截；其他 Nginx location 字节与响应保持 |
| Codex | 缺凭据页面显示未连接；真实宿主桥接进程使用 mock-response，在页面提交、队列、模拟回复及 SSE 完成；会话属于新运行期；真实模型调用为零 |
| 中断续传 | 与 SSH 相同的二进制控制器运行在本机子进程；在 SAVING 的 app.tar 第 65,536 字节断流，服务在线、前版 clean 保留、下一操作被拒绝；原命令续传及重复回执通过 |
| Nginx 失败 | 实际 Nginx 校验子进程失败后，修改前配置 SHA、挂载读回和 inode 一致；执行正常 reload |
| 保留和空间 | 两个 clean 槽、一份实例，scratch 完整归档数为零；逐阶段记录目录分配字节、PG 卷、镜像清单、宿主及 Docker 文件系统剩余空间 |

本机演练包明确标为 `UNVERSIONED`，不能通过远端发布入口。提交后的精确版本包另以其 manifest 与恢复回执核验；不能把开发包声明为精确发行版本。
