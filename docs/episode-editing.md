# 成片剪辑

“生产制作 → 成片剪辑”把已选素材组织为每集一个可编辑工程、多个不可变成片。它不改变镜头原件、素材候选或故事输入。故事项目负责选材和剪辑判断；本系统负责准确保存、合成、播放、评论和恢复。

## 使用路径

初次进入选第一集，之后恢复上次选择。播放器和多轨时间线始终读取所选不可变成片中的同一工程快照。版本、字幕与缩放沿用共用筛选。正文以全宽多轨时间线为主体，播放器保留既有尺寸上限；桌面与窄屏均无场镜侧栏或筛选下载区。页面只供观看、选择与评论，后台工程保存、编辑和渲染仍由 API／CLI 执行；页面不读取、应用或清除以前保存的本机工程草稿。

普通点击画面、声音、字幕、人名条或片头尾，会暂停播放并打开素材所属的既有实体、状态或镜头大卡，选中成片实际使用的候选、原件和条目。大卡顶部的“评论此片段”绑定成片的轨道片段；“源素材评论”绑定原素材，两者共用原评论系统。来源缺失或归属漂移时保留原身份并提示，不能改开其他素材。关闭大卡后保留成片版本、播放帧、缩放、滚动和选择；键盘激活片段等价开卡并定位片段起点。

时间线左上角固定格中的“选择”按钮带多轨图标，默认关闭；普通状态保留范围数值但禁用四个输入及循环、评论、清除操作。开启后暂停播放，在轨道绘图区横向拖出时间、纵向触及轨道，可反向拖动或跨空隙；新的框选替换旧选择，首次进入没有范围。选择模式下直接点击轨道名称或用 Enter／空格切换轨道，支持非相邻轨，改轨道不改时间。普通状态轨名只供阅读。

再次点击选择按钮或在输入框、评论编辑器之外按 Esc 退出：保留范围、轨道、播放帧、滚动和评论草稿，停止循环并撤掉可编辑高亮；重新进入恢复同一准确成片的选择，循环须重新开启。“清除选择”清空时间与轨道并停循环，仍留在选择模式。拖动中 Esc 只撤销本次拖动，恢复拖动前选区。轨名与标尺不参加框选，没有拖动的单击不提交选区，也不开卡。历史范围评论在普通状态可定位准确版本与范围，以虚线展示历史锚点，不覆盖保留的可编辑选择；切集、切版本沿准确修订隔离。

范围提供起帧、止帧和对应的分:秒.毫秒四个输入。整数帧是唯一精度依据，范围为起帧包含、止帧不含；改帧立即换算时间，改时间按工程有理帧率取最近帧，Enter 和失焦回显对齐值。非法、空、负数、越界、倒置、零长、未选轨道或没有相交素材时均禁止范围评论。24 fps 下 492 帧为 20.500 秒、714 帧为 29.750 秒；6838 帧真实尾点为 284.916667 秒，显示的 4:44.917 不会改动尾帧。

时间线上方右侧先显示只读“当前帧”，经分隔后为五级缩放；播放、暂停定位与拖头均更新实际帧，普通状态继续可用。角格与轨名在横向滚动、缩放及尺寸变化后固定可见。普通模式下可在标尺或轨道空白定位播放头，拖动红线时暂停并逐帧移动；红线不遮挡素材点击。播放跟随进度滚动，选择时暂停跟随。“全片概览”铺满可用宽度，其后三级为 2／4／8 倍，“逐帧”至少 16 倍且每帧至少 4 像素。缩放与尺寸变化保持播放头相对位置，固定轨名在横向滚动时可见。声音明确区分原片混合轨、声底和补录。六份交付组件、后台导出与媒体访问接口继续保留。

## 对象与时间单位

时间线把同一浏览器帧内的移动合并为一次绘制，手势内复用几何信息；滚动、缩放或尺寸改变后重新测量。滚动位置最多每 250ms 写入本机存储，手势结束、暂停、版本切换与离开页面补写终态。销毁时取消待绘制帧、观察器和失去用途的读取，保留已保存的审阅位置。

范围评论在事务前预读画面、声音和字层的准确原件，事务内再核最新关联、实际归属和物理身份。预检后原件或关联变化仍拒绝，原草稿与范围保留；已有评论的相同 ID 重试沿原幂等规则返回，不因后来新增关联改写历史评论。

| 对象 | 行为 |
| --- | --- |
| `EPISODE_EDIT` | 每个视听集一个工程，以 `expected_version` 乐观并发保存；过期写入拒绝。 |
| `EDIT_SNAPSHOT` | 提交时冻结工程、准确依赖和渲染引擎；不可改写。 |
| `EPISODE_FILM` | 一个快照对应一套不可变交付物；与镜头素材及生成调用分开。 |
| `EDIT_ASSOCIATION` | 对准确历史成片追加的素材关联；内容寻址、逐版单链，不修改原工程或媒体。 |

工程格式为 `episode-edit-v1`。`episode` 固定集对象及修订；`sources` 固定素材对象/修订、候选、完整组件及实际探测的流规格。`tracks`、`clips`、`markers`、`subtitles` 和 `titles` 分别表达轨道、编辑片段、场位置、对白/唱词字幕和片名/署名/人名条。可选 `method_execution` 绑定该集的准确方法执行。

视频源入出点使用源整数帧，时间线位置和淡变使用工程整数帧；音频源入出点使用源采样，时间线及淡变使用工程 48 kHz 采样。所有出点不包含，帧率保存为有理数。源入出点与时间线位置独立；归一化时长由真实流规格计算。画面须完整覆盖工程，只允许显式叠化的重叠，缺口、越界、零长片段、失效依赖或原件变化均拒绝。

原生工程支持声画不同切点、多个声音叠加、音量/淡变、画面裁切、局部原字幕去除、基础亮度/对比度/饱和度、叠化、片名及中文字幕。它不是外部 NLE 工程，也不提供复杂特效或自动选材。

人名条使用 `titles` 中的 `style: nameplate`，在独立轨道中显示。姓名最多 12 字，可另有一行不超过 24 字的身份说明；起止帧与四角位置由后台工程指定。`position` 可为 `lower-left`、`lower-right`、`upper-left`、`upper-right`，缺省左下。字幕版和无对白字幕版均保留人名条，SRT 仍只含对白与唱词。

## 素材关联与评论

普通实体是故事逻辑组成，AV_SHOT 是独立并行的镜头身份。为镜头表达制作的字层归对应镜头；人物姓名只是人名条的身份来源。字层是具有真实 JSON 原件的 `text-layer/project` 素材，可直接外部登记，不需要伪造生成调用或素材需求。原件中的稳定 `entry_id` 区分每条文字；跨镜使用通过统一关系表达，唯一出处不变。多个成片版本可以使用同一素材的不同原件组件。

历史成片的追加关联固定 output 对象与修订、元素类型和 ID、稳定轨道、文字／时间摘要、准确 candidate/component/entry、制作出处和原始提交依据。关联有版本、前一版与摘要，评论固定创建时的关联；新关联不改旧评论，亦不声称旧渲染已使用事后登记的素材。新的可编辑工程可在字幕和 titles 中以 `material_ref` 引用真实条目。

时间评论的 `edit_selection` 保存准确 snapshot、association、整数帧、轨道集合和全部相交元素。轨道 key 为 `track:<工程轨道ID>` 或 `text:subtitles`、`text:nameplates`、`text:titles`；元素身份是轨道 key、类型和 ID 的组合。服务端依据冻结工程重算半开区间相交集合，并校验素材、提交依据与关联；新评论还核当前归属和最新关联，已有意见保持原依据。旧无轨道时间评论仍是混合成片范围，不推断全轨。`comments/context` 与完整导出保留同一锚点。

## HTTP 与 CLI

浏览器和 CLI 共同调用 `editing_api.dispatch`。HTTP 使用 `POST /api/editing/{action}` 与 JSON 请求；CLI 从 `--request` 读取同一 JSON：

```bash
PYTHONPATH=. python3 -m review_desk --instance /path/to/instance edit validate --request validate.json
PYTHONPATH=. python3 -m review_desk --instance /path/to/instance edit save --request save.json
PYTHONPATH=. python3 -m review_desk --instance /path/to/instance edit submit --request submit.json
```

| action | 请求内容 |
| --- | --- |
| `catalog` | 可选 `episode_id`，读取工程及可用成片；`summary=1` 仅返回集与成片准确引用，供页面随后 `get` 选中版本。 |
| `get` | `object_id`，可选准确 `revision_id`；返回完整工程或成片。 |
| `review` | 准确 `object_id`、`revision_id`，可选 `association` 引用；读取轨道、元素及其素材。 |
| `associate` | 完整 `association`；原子追加校验过的关联，不覆盖或分叉。 |
| `validate` | `project`，校验结构、依赖、原件和流规格，不保存。 |
| `save` | `project`、`expected_version`；首次为 0。导入使用同一入口，导出使用 `get` 或成片工程组件。 |
| `submit` | `project_id`、`expected_version`、`task_id`、`request_id`。 |
| `status` / `cancel` / `retry` | 任务 `id`；重试仅允许失败、取消或中断的任务，每快照累计最多三次。 |

提交以准确工程及引擎生成持久指纹。重复请求不产生重复输出；未知结果先查状态。每实例只允许运行一个独立 worker：

```bash
PYTHONPATH=. python3 -m review_desk --instance /path/to/instance serve --render-worker
# 或由进程管理器分别启动 HTTP 与下面的独立 worker，勿同时重复启动：
PYTHONPATH=. python3 -m review_desk --instance /path/to/instance edit-worker
```

队列、进度和进程状态在 `.runtime/edit-render.sqlite3`，worker 持有 `.runtime/edit-worker.lock`；两者不进入业务导出。FFmpeg 在数据库写事务外运行；校验六份成品后才原子登记。重启核对已登记结果，将未完成任务标为中断，等待显式重试。取消会终止本任务子进程；Linux 父进程退出时也终止 FFmpeg。HTTP 与 worker 登记均参加实例 `http-write.lock` 的共享锁，正式发布需取得排他锁并协调所有写入进程。

## 渲染与恢复

Dockerfile 提供 FFmpeg、libass、Noto CJK 字体及 tini。目标实例仍须真实试渲染中文字幕；仅安装软件或健康检查成功不等于渲染可用。声音以 48 kHz、24-bit PCM 混音，输出 H.264/AAC；混音采用两遍响度规范化，目标 −18 LUFS、−1.5 dBTP。源编码仍如实记录，PCM 派生不代表源内容无损。

每套输出恰好含 `subtitled`、`clean`、`mix`、`project`、`subtitles`、`source-map` 六组件。校验不仅核哈希，还核视频尺寸、帧数、帧率、起点、声音编码/采样数，以及 JSON、SRT 与冻结工程的语义一致性。无对白字幕版仍保留片名和画内文字。

Schema 15 完整导出包含工程、快照、成片、字层原件、关联单链、准确来源及评论；运行队列不导出。Schema 14 旧完整导出在不含剪辑对象时仍可恢复。恢复只进入空实例，原件和业务依赖先预检；恢复后新队列可按工程重新提交。实例发布须使用增量及版本检查，保全新评论和历史，不能用任务快照覆盖活库。具体正式窗口和镜像切换由故事项目管理。

自动验证见 `tests/test_editing.py`、`tests/test_editing_recovery.py`、`tests/test_editing_review.py`、相关 bundle 与前端测试。它们与实例实际 Chrome 操作、完整作品观看、人耳听感及用户接受分别记录。
