# 制作页面的读取边界

制作页面首开只读取共用配置、评论、编号和引用目录。资料目录使用 `/api/sources?with_revision=1&metadata=1`，保留资料名称和准确修订；剧本目录使用 `/api/screenplays?metadata=1`，保留版本、集场及准确链接，不携带正文 blocks。进入故事创作后再读取完整资料、结构和剧本。同一窗口的首次正文读取共用一组在途请求；失败可重试，切换后的迟到结果不改变当前页面。刷新重新读取，草稿继续使用原来的准确对象与修订键。

实体和素材管理直接使用各自响应中的分集目录。素材管理请求 `grouped=1&compact=1`：返回全部分组身份、小卡信息、计数和筛选结果，分页仍在当前窗口完成。完整关联证据在打开大卡时读取；不带 `compact` 的接口继续返回完整列表投影。接口未新增固定结果上限，素材数与分组展示数仍分别统计。

服务端列表读取直接取修订封套中的身份、归属和媒体信息；内容寻址字段只展开列表关联所需的准确输入及复用方式。详情、写入验证和历史记录仍使用完整修订读取器。镜头目录从方案成员和定义来源读取评论目标，不为统计评论展开各版本的完整提示词。所有版本及候选的评论目标仍保留。

## 请求内复用与一致性

`production.read_scope` 在一个 SQLite 读取事务内复用数据，退出时无论成功或异常都清除。它不保存跨请求的业务结果，也不改变调用者已有事务的所有权。

| 对象 | 准确键与依赖 | 生命周期与空间边界 |
| --- | --- | --- |
| 当前记录集合 | 当前 Store、事务快照、所需 kind 集合；全量读取可服务其子集 | 当前请求访问的种类集合；不因只需关系记录而展开其他种类 |
| 完整修订与旧版本归属 | 对象及准确 revision；material_members | 当前请求访问的修订，每项一次归属查询；返回值继续独立解析 |
| 列表元数据 | 对象＋准确 revision；修订封套、所需内容节点 | 当前请求访问的记录和路径，不展开无关正文 |
| 内容节点 | 内容 SHA-256；material_content 的校验通过节点 | 当前请求涉及的唯一节点；读入校验哈希，失败不形成成功结果 |
| 素材身份与总量 | 当前事务的别名表、方案版本、候选成员 | 每请求一份映射，总量只算一次；返回单项计数副本 |

这些集合的空间随单次读取涉及的权威记录数变化，不随服务运行时间、历史请求或访问次数累积。HTTP 服务保持单线程、一个 Store 连接，不新增工作线程、跨进程缓存、TTL、外部缓存服务或持久摘要表。写入没有缓存失效消息：前台评论、采纳、参考选定和后台导入／发布完成后，下一请求从数据库建立新快照；其他进程提交后亦如此。正在执行的读取保持原快照，不能混合两个版本。重启无需任何残留值。

## 运维与验证

没有数据库迁移、WAL 切换、媒体物化或新配置。原件服务、Range、存储路径和字节保持现有契约。恢复使用实例的准确上一版代码和服务镜像，保留活库与原件；不需要清空缓存或回灌数据库。浏览器刷新即可重新初始化页面数据，不能清除用户草稿来恢复服务。

对应自动检查覆盖目录／正文一致、组合筛选和分组、准确历史、写后再读、并发读取快照、迟到导航及读取失败。实例规模、逐路径两轮前后样本、六方向取舍和真实浏览器／正式发布结果由故事实例任务交付包记录；自动检查不替代这些验收。
