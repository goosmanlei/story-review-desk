# 实体卡读取的性能与一致性

`/api/production/entity-review` 在一个请求内复用已读取的原始行，并用一个 SQLite 只读事务保持对象头和历史引用一致；返回后立即清除复用数据。每次请求仍重新读取当前数据、检查准备范围、准确引用和评论，不保存跨请求响应缓存。

优化消除了同一实体聚合中的多次全量当前记录读取和重复生成上下文计算；`material_members_revision` 索引按准确修订查询素材轮次。索引在 Store 初始化时幂等建立，不改变业务表、不可变修订、评论和导出格式。记录投影每次独立构造，避免同一原始行的展示字段互相污染。

`tests/test_entity_read_scope.py` 核对实体、状态、方案、素材、关系、评论和导入后下一次读取，历史范围不被新方案改写，异常后缓存及事务释放，嵌套读取不回滚调用者事务，并执行导出后空实例恢复。并发读取样例使用 WAL 验证单次快照不混用新旧对象头；默认单线程 HTTP 服务的写入仍按既有事务协议执行。

性能验收须在同机、同数据与相同请求集合下测完整 HTTP 响应读取。每类至少 50 个预热后样本，首次和预热另列；P95 用排序后向上取整的第 95% 位置。不能以缓存命中率或缩减响应代替验收。实际实例的前后代码版本、数据规模、原始样本、响应比较、机器配置及页面操作证据由实例仓库交付，不把通用测试耗时写成正式页面验收。
