# 通用软件工作规则

默认中文。先读 README、本文件、STATE，再按任务读取所选实例的当前发布指引；不加载全部历史或整套资料。软件说明不构成故事事实。

## 边界

- 软件与故事分开维护。每项目绑定一个独立实例；只读显式 REVIEW_INSTANCE_ROOT，不从父目录、旧导出或同名文件推断业务来源。
- 已发布数据库修订是业务权威。候选、正式审阅、采用、源同步、生成授权与实际产物分开；写入走受控服务、精确 CAS 和事务，历史只读追加。
- 媒体必须绑定永久身份、版本和 SHA。文本检索不等于完整读取，文件与元数据不证明听音或看图；缺项标 UNKNOWN。
- Codex 默认讨论；受控执行只限本轮明确权限和白名单，实际动作返回事务回执。模型调用、正式审阅或制作采用仍各自核对授权，结果未知先查状态，不盲重试。
- API 配置只保存密钥环境变量名；不把密钥、私有会话、数据库或故事媒体提交软件仓库。Web 不直接写正式源或调用制作模型。
- 备份恢复保留业务身份与不可变历史，重置运行期，不恢复凭证和活跃执行资格。新故事必须 create，不能复用旧故事数据库。

## 维护与交付

- 通用软件在已绑定的 GitHub 公开仓库迭代；验证后提交并正常 push，不强推。故事项目另用私有仓库，创作进展通过受控业务快照提交；软件包只由精确核心版本生成。
- 故事项目会话可发起并协调通用开发；通用代码与 Skill 只在核心源码维护，故事项目仅消费固定版本的受管副本。通用改动在核心验收后，再显式升级故事项目，不维护第二套通用源码。
- 持续压缩项目指令：README 导航，AGENTS 稳定边界与任务路由，STATE 当前事实和待办，专题各管一个职责。入口只保留跨任务仍有效的信息，不积累日志、完成 Case 或工具输出。
- 持续清理已核验无效的代码、过程文件和数据；先核对引用、运行占用与恢复方式，保护来源、有效媒体、正式历史、唯一工作、凭证及有效备份。
- 验证按风险覆盖语义 QA、类型、构建、隔离 E2E、真实 Docker 与正式端口；只读 Sites 另核对精确项目提交、核心版本、快照和原访问范围。计划、测试端口或 pending 不能称部署完成。
- 扩展业务模块时同时更新共享工作投影、系统审计依据和相关测试，不能手工维护第二份进度。
