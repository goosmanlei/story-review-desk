# 工作方法：配置怎样进入实际执行

在“系统管理 → 工作方法”先阅读方法与所引准确共用章节。默认页面显示用途、正文、版本和实际后续使用范围；维护执行配置由单独入口承接。已开始的工作继续原版本，不随当前选择变化。

文件目录可打开正文、表格、图示与来源；“下载当前准确文件”保留原字节。打开所引共用章节后用“返回原阅读位置”回到方法。方法和共用资料切换保留准确对象、文件及位置；准确读取失败时明确报错，重试仍取原版本。

圈选单个文件内的原文可保存评论，包括连续跨段摘录；评论固定修订、文件、段落与真实摘录。“查看评论”默认汇总同一方法或资料所有版本、所有文件的未关闭意见，按原评论身份去重，包含尚未回应的旧意见；原版本和文件标在意见卡上。关闭后从“展开历史”回查，重开回到待处理范围。

“定位原圈选”在既有复核浮窗读取原准确文件；可分别打开真实回应稿与当前稿，返回保持方法、文件、位置和底层草稿。新版改名或删除文件不会迁移旧锚点；回应时明确选择实际对应的当前文件，当前稿缺原文件时可主动阅读当前稿的全部文件。读取失败明确报错，重试仍指原准确目标。项目源资料同样可评论，正文仍由唯一源维护。

“编辑正文”修改当前准确文件，保留其他文件、元数据、原条件类型和值。选定现有工作类型／条件分支后点击“保存并用于所选后续工作”，只改变这些后续选择；“仅保存待用”不改绑定。方法保存成功但部分应用失败时，页面分别列出已应用和未应用范围，刷新保留改稿和保存回执。“核对当前使用范围”读回当前分支，检查后再继续；准确重试不复制方法或绑定。正文已被别人更新时，先核对最新正文，显式合并当前文件；其他文件和元数据沿最新版本保留。

普通正文编辑的本机草稿在浏览器存储可用时跨刷新恢复；它不替代已保存版本或备份。传统维护配置表单仍只保留本页未提交输入。

## 维护与取得

方法包含 `SKILL.md`（`name`、`description` 头部）、用途、适用条件、输入、产物、检查、必要步骤，以及按需参考、模板和确定性工具的文本文件。方法包使用普通相对路径，不依赖模型厂商或本机技能安装目录。系统保存并交付工具文件，不自动执行任意脚本。秘密、账号信息和运行私有路径不属于方法正文。

共用资料按具名章节引用。两个方法可以引用同一资料的同一准确修订；资料改版后，需显式修改方法中的章节引用，再更新环节绑定。条件为字段和值的匹配；匹配规则中条件最多者优先，同等具体但不唯一时拒绝执行。失效章节即使当前条件不加载，也不能静默跳过。

加载条件和方法选择条件使用同一编辑规则。页面回读准确 JSON 值；只修改用途、正文或方法版本时，未编辑的条件类型和值、章节顺序和准确引用保持。布尔 `true` / `false` 与文本 `"true"` / `"false"` 不混淆。例如 `{"need_staging":true}` 选择按需调度资料，`{"media_type":"video"}` 选择视频方法。空输入或 `{}` 表示无条件。

单个简单条件仍可写成 `media_type=video` 或 `need_staging=true`；前者为文本，后者为布尔。字面文本请加双引号，如 `need_staging="true"`。多个字段、含逗号的文本、数组和对象建议使用完整 JSON 对象；数字、`null`、数组、对象沿已有相等比较规则匹配。重复字段（包括嵌套对象内）、空值、无效 JSON 和非有限数值整次拒绝，指出条件行并保留当前输入，不追加部分版本或改变绑定。这里的空值指缺少值的 `字段=`；JSON `null` 是有效值。原解析器以 `conditions.get(k) == v` 比较，空值与缺少请求字段、数字与布尔的既有 Python 比较语义仍保留。

HTTP 编辑器的 `GET /api/methods` 另返回 `condition_texts`，以修订号映射到各资源／规则的准确 JSON 文本数组。`POST /api/methods/save` 可携带同名数组，顺序与待保存的 `resources` / `rules` 一致；服务端在保存前统一解析，避免浏览器将大整数舍入。资源的 `null` 文本条目表示原引用未声明 `when`，保持其省略形式；规则必须是字符串，空字符串解析为 `{}`。该传输字段不进入定义、依赖或执行快照；直接提交 `when` 对象的 CLI / API 契约继续有效。

页面编辑使用版本冲突检查。收到“此项已被更新”时保留当前输入，先核对已保存版本再合并；不能再次点击保存就覆盖别人。维护配置表单切换本页标签可保留草稿；普通正文编辑的刷新恢复按上文说明。

带 `project-markdown` 来源的资料是项目 Markdown 的只读投影。页面不能反向编辑它；项目通过 `method-source` 校验来源路径、章节、全文摘要和投影摘要，追加新版本。其他资料的有效正文在方法账本。导出包是准确快照，不与活库形成第二个可独立编辑的正文源。

## 执行契约

一次工作由 `work_type`（工作类型）、`run_id`（运行）、`step_id`（步骤）、`target`（目标）共同定位。准备接口返回完整方法文件、适用共用章节和准确输入，并建立不可改写的执行记录。相同身份重试只允许原输入；更换输入或方法应显式新建步骤。

1. `GET /api/methods/resolve?work_type=…&conditions=…` 只查看当前选择。
2. `POST /api/methods/prepare` 提交身份、条件和 `inputs`，必要时带冻结 `binding`。返回准确执行记录。
3. 执行者读取实际返回内容，按 `package.steps` 保存阶段产物到 `POST /api/methods/artifact`。请求包含同一身份、准确 `execution`、原 `inputs`、`stage` 和 `output`。缺少前序阶段、身份不符或改写已冻结产物均拒绝。
4. 消费方必须核对产物与准确输入、目标及结果一致，不能接受布尔值“已使用方法”。恢复仍检查原方法与共用资料是否完整。

`GET /api/methods/record` 按对象和修订读取。CLI 与 HTTP 共用同一逻辑：在系统目录执行 `python3 -m review_desk --instance <实例> methods`、`method-save <JSON>`、`method-prepare <JSON>`、`method-artifact <JSON>`、`method-get <对象> --revision <修订>`。`method-export <执行对象> <执行修订> --output <新目录>` 导出文件、章节、准确输入和恢复登记包。

`GET /api/methods/stage?execution_object_id=…&execution_revision_id=…&stage=…` 只读核对冻结执行、真实方法阶段、产物身份、服务输出摘要及全部前置依赖，返回 `artifact` 和有序 `previous` 准确引用。`artifact: null` 表示服务尚无该阶段确认，不表示完成；此入口不创建执行或产物。旧完整产物仍返回完整值；当前制作摘要中的 `output.sha256` 是原提交 JSON 值的摘要，`output_sha256` 是压缩输出外层摘要，不能互换。媒体草稿/定稿另核对 requirement 与 generation 的各自摘要。作者端保存本机原值并据此核验回读，服务不恢复制作草稿全文。

## 已接入的边界

| 环节 | 实际交付和校验 |
| --- | --- |
| 评论润色 `comment-polish` | Responses 请求包含所选方法全部文本文件、适用资料和准确评论上下文；方法占用同一总字符预算。原文、模型参数与建议手动采用边界保留。每次建议有独立执行和结果，私有记录不进入公开作品导出。 |
| 外部作者与读者 | 使用通用 HTTP 契约；故事项目实现自身的检查点、阅读位置和请求构造。系统不导入故事创作脚本。 |
| 媒体方案 `media-plan` | `media-prepare` 固定准确需求、源块和原方案。草稿、回读、定稿各有产物；草稿和定稿按既有生成方案格式检查。登记新方案时核对最终内容，不能借用另一对象或步骤的回执。 |
| 媒体准备与调用登记 | 生成准备包包含方法依据及独立方法快照；最终模型 Prompt 仍仅为方案 Prompt。准确原件、局部范围、模型输入契约与未定原词闸门保留。新 CALL 必须与准备包的准确方案、方法、Prompt、参数、渠道和输入一致。 |

参考候选、片段或既有路线的选择沿用原 UI。这类确定性操作记录准确父方案和选择请求，核对只改变许可的输入或选项，不宣称重新完成了创作方法。撤回／必需性调整同样只允许管理字段变化。来源方案的方法历史未知仍为未知；这些操作不能夹带新 Prompt、模型参数或创作要求。后续真正改写方案必须取得新的 `media-plan` 步骤。

## 启用、公开导出与恢复

实现沿用现有 GUIDANCE、NOTE 和修订／依赖表，没有新增 Schema。方法、资料、绑定可编辑为新版本；执行、阶段产物与启用记录不可覆盖。

媒体强制约束通过显式 `method-activate-media` 在协调后的正式写入窗口启用。它只记录当时库中已经存在的准确方案修订及内容摘要。旧方案保留未知方法历史；切换后的新创作方案必须走实际方法。没有按任务编号永久豁免的入口。启用前须由实例项目核对在途交付；发布锁本身不排除页面/API 写入。

`method-registry` 导出方法定义历史及本实例启用记录；需要跨实例配置迁移时只选方法／资料／绑定，不能把另一实例的冻结范围复制为豁免。`method-restore <JSON>` 校验摘要、连续版本、准确依赖和执行快照，原子追加；目标同版内容不同或已经前进时拒绝覆盖。公开完整导出继续使用现有 Schema，保留公开方法与制作关联，排除标记为私有的执行和阶段产物；显式执行导出可用于私有运行恢复，应按原运行范围保存。

完整实例恢复仍走 `restore`，同时校验方法定义、执行、阶段依赖和制作关联。方法配置恢复不能替代作品、评论、准确选择、原件和运行库恢复；切回旧代码也不等于恢复数据库。具体部署、协调窗口、备份与验证由实例项目负责。

确定性校验能证明交付了什么、用了哪些准确输入以及阶段产物怎样关联，不能证明模型内部理解。页面操作、受控请求、独立实践和外部真实调用应分别报告。

## 投影的图示与来源文件

`method-source` 可选 `preserve_paths: true`，让完整章节保留项目相对路径；`companions` 将章节名映射到其必要附属文件路径数组，支持项目内 Markdown、SVG 和 JSON。附属文件同样记录原文摘要、进入准确资源版本和导出恢复包。仅所选章节的附属文件进入执行包，不把未选章节全文拼入模型指令。缺文件、越界、切片与同名原件冲突均拒绝；不允许从管理页面反写源投影。未使用该扩展的历史包仍保持原摘要。

媒体 `media-prepare` 可附 `method_conditions`（不能冒充其他 `media_type`）与 `supporting_references`（最多 100 条准确引用）。返回的冻结输入含补充文档原文；其外层引用必须存在并通过源校验，文档内部提到的退役历史仅为只读证据，不重新登记为生产依赖。媒体定稿消费时再次核对补充文档，换材料或条件须新步骤；旧请求无这些字段时保持原协议。

制作域启用当前内容模型后，新方法执行的输入与产物只持久保存摘要、所用方法、必要事实及结果指向；完整工作稿限于任务检查点。实际生成提交另存准确方案快照。已有方法正文、绑定及过去执行仍按原版本保持，不能换名复制后续每份制作稿。详见 [当前制作与候选](material-versions.md)。

## 准确正文与原件接口

`GET /api/methods/document` 使用对象、准确修订和文件名，返回确定性 Markdown 阅读块；评论段落标识由原文件行位置派生，不改保存正文。`POST /api/methods/edit` 接收 `object_id/base_revision/changes/scopes`；每个范围指向已有绑定的准确修订及规则 `index`。返回 `saved/applied/unapplied`；继续应用时携带原 `saved_revision`，不建立审批或独立应用记录。`POST /api/methods/respond` 接入已有 `comment-handling-v1`。

源投影中的 PNG/JPEG/WebP、MP4/WebM、MP3/WAV 相对链接在 `method-source` 时记录项目相对路径、字节数、SHA-256 和 MIME。`GET /api/methods/media` 先按准确资源版本核对原件，再返回原文件；源投影没有摘要、原件缺失或字节变化时拒绝替代。原件沿实例项目的受管资源交付，不复制成可编辑资料库；恢复实例须同时具备这些准确原件。SVG 等文本附属文件仍随准确资源保存。历史无原件摘要的版本不能凭当前文件补造媒体身份。
