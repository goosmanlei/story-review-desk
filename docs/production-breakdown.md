# 视听制作：目的、关键状态与生成方案

顶部选择视听集，左侧选择场镜。每镜除识别标题、准确故事依据和直接评论外，只有按顺序呈现的叙事目的、镜头关键状态、生成方案。集场工作稿不占正文；停留约一秒或键盘聚焦时读取，可移入提示层，离开关闭。它是一份可覆盖更新的当前说明，与不可变的场镜组成分开。

## 准确组成与内容

`AV_EPISODE.scenes` 和 `AV_SCENE.shots` 继续引用准确修订。`input_lock`、`sources`、故事范围和对象／修订配对校验保持。地址可保存 `breakdown_episode_revision`，但不提供集场计划版本选择器；这项身份用于恢复准确组成，不承担说明版本管理。失效或歧义链接报错，不能按标题或最新修订猜测。

当前写入使用 `reading_contract: audiovisual-three-part-v1`。集场仅保存准确组成；镜头保存 `purpose`、`key_states` 和 `products`，另保留来源、既有时长与实际身份依赖。`purpose` 解释本镜给观众的新理解或感受，不由系统按动作模板生成。

`key_states` 是有独立素材准备需要的镜内时刻。每项含稳定 `id`、自然语言 `description` 与准确 `requirements` 引用；同一状态可关联多个需求，同一需求不能重复占据两个状态。需求须属于本镜对象，允许显式复用本镜较早设计下的准确需求；不能借另一镜需求。没有中间状态就不制造占位。

`products` 按真实制作顺序保存 `{label, requirement}`，页面按此顺序设 Tab，初入选择第一项，返回仅恢复本镜仍合法的选择。上游参考不自动成为产物。缺少准确需求、没有产物或没有模型方案分别显示具体空态。工程保持工程身份，通过共用卡读取 ZIP 等原件和交付要求，不冒充生成视频。

每个 Tab 直接显示纯参考列表、模型／参数、完整 Prompt。版本按钮在 Tab 内；切版后这三项取自同一准确定义，冻结版无定义时不借用当前计划。需求绑定到一个未成为独立制作版本的历史修订时，仍读该准确修订，不以身份最新值覆盖。真实 CALL、候选比较、原件判断及实际采用保留在共用素材卡。

参考列表保留真实输入的素材身份、制作版本、候选、文件组成和裁切／时间范围，不展示用途意见或重复审阅说明。“？”复用操作旁的共用审阅帮助，不构成第四节。共用卡关闭后恢复镜头位置及产物选择。卡内准确历史素材所属状态优先于当前作品的默认状态，不能因状态对象相同便切到其新修订。

## 当前工作稿与准确反馈

`audiovisual_notes` 每集／场一行，`body` 最长三万字；读取随集场导航返回；`POST /api/production/working-note` 使用 `object_id` 和 `expected_etag` 防止覆盖并发更新。更新不产生设计修订或历史副本；不允许为镜头写这类工作稿。完整导出保存当前正文与更新时间。

叙事目的、状态描述、参数和 Prompt 沿原对象／修订／字段的文字锚点反馈。连续跨块和分段圈选保持准确端点，保存／刷新／关闭／重开不改绑。详见 [评论范围](comment-checklist.md#组合阅读中的准确文字范围)。已有 `production_reading`、`scene_reading` 是其他阅读入口的准确投影能力；视听镜卡不再据此建立动作对白或共同条件副本。准确 Prompt 和锁定剧本继续保存影片实际要表达的内容。

集评论计数覆盖该集准确组成与直接素材的定义、候选，含已关闭评论且去重；不混入无关上游或故事评论。来源按钮读准确故事场并高亮引用范围；来源缺失不回落同名或最新版。

## 素材关系与执行路线

实体、素材需求／原件与镜头的当前关系统一为 `RELATION/business`，以稳定对象对确定唯一身份；具体事实、阶段约束与准确来源写在同一份正文中。旧 `MATERIAL_RELATION` 只供准确历史读取，不再写入。生成方案各输入固定准确关系修订，并独立保存 reference、reuse、variant 等执行语义；普通相关、未选备选及没有执行语义的说明不会自动成为输入。关系编号、反写与修订规则见[统一关系契约](materials-and-relationships.md#关系契约)。

必需参考参与当前路线校验。可选参考由 enabled 决定；条件参考需明确判断条件；one_of 参考必须为其 group 选择 route。计划的 selected_routes 与 conditions 参与冻结定义。只检查当前执行路线的缺项和循环，不能让未选路线误阻断，也不能让描述关系自动提交输入。

`POST /api/production/material-route` 使用操作 id、requirement_id、expected_revision、plan_number 及 action/key/value。route 的 key/value 是组和路线；condition 是条件名和布尔值；optional 是输入索引和布尔值。接口校验准确计划和可用选项，冻结方案修改建立新版，操作 ID 重试幂等。

## 准确参考选择

小卡和 Prompt 标记通过原始有序输入槽位打开同一详情。直接参考可“选为方案参考”；间接参考只读，并指明其上游所有者，不能静默改写共享需求。浏览、比较、选择参考和实际采用互不推断。

`POST /api/production/shot-reference` 接收 id、requirement_id、expected_revision、plan_number、index、input_key，以及 material_id、number、candidate、component_id 和可选 crop/range。candidate 是准确对象／修订引用；null 表示仅选版本，仍缺候选。input_key 来自服务端原槽位指纹。图像范围使用归一化坐标；音视频范围用秒并须处于原件内。

已选入口携带服务端槽位的 `baseline_id`（当前素材版本编号所依据的收敛身份），与普通准确素材链接共用版本校验。没有基线的旧链接继续按既有映射解释；删除身份、失效基线和不属于该版的候选拒绝读取，不改为最新版本。

保存回执返回消费需求的准确 `revision_id`、素材方案 `number`、`baseline_id`、`frozen`、全部 `slots` 及 `selected_index`。后者是新草稿中的输入位置，可能不同于冻结调用只含有效路线时的位置。下一次保存使用回执中的准确修订、方案号与新槽位指纹；同一操作编号只可重发相同请求。

消费小卡直接显示已保存的时间范围或已登记裁切。详情中的相同选择显示已保存，编辑后变为“保存修改 · 未保存”；放弃范围修改恢复已保存数值。编辑值按素材版本、候选和文件组成分别保留，切换只用于浏览，试听／预览组成不能作为原件保存。空数值先拒绝，其他范围校验继续由服务端负责；失败保留当前编辑值。

音视频参考的范围控件紧邻播放器。“试听已保存片段”直接使用此消费位置保存的准确版本、候选、组成及起止；调整后变为“试听未保存范围”，只有明确保存才推进生成输入。放弃恢复保存值，修改范围时暂停正在试听的旧范围。播放器的完整播放入口明确区分原件和预览，从文件起点播放全长；暂停控件表明当前播放的是已保存片段、未保存范围、评论选段还是完整文件。评论圈选与参考范围独立，试听参考不建立评论圈选，清除评论选段也不扩大参考试听。关闭、切换及读取失败沿原生命周期保护，不替换准确文件。选段终点另按真实媒体时间调度，避免仅靠低频 `timeupdate` 事件迟停。

一次保存只绑定发出请求时的消费方案和位置。响应推进该编辑会话的准确身份，但不会覆盖保存中继续输入的值或将已保存提示刷到另一候选。关闭时仍有请求就等待其结果，再回到原消费位置刷新；进入其他卡时先等待返回，不重绘新读卡。已切换页面或失效的原消费入口不会接收迟到刷新。选择成功不替代素材方案采纳、原件认可、文件和谱系等生成准备条件。

回归入口为 `tests/shot_reference_loop.test.cjs`、`tests/media_location.test.cjs`、`tests/ui_unification_compatibility.test.cjs`、`tests/version_consolidation.test.cjs` 与 `tests/test_shot_references.py`；真实浏览器、实例版本与正式数据保护由实例任务留证。

替换原件而未再次提交范围时清除旧 crop/range，不能把另一候选的范围带入新原件。其他槽位不变；冻结后建立新方案，真实调用和旧意见不变。同操作 ID 同载荷重试返回原结果，不同载荷拒绝。读取中切换、关闭或转工作区后，迟到响应不覆盖新对象。保存后等待弹窗历史返回再刷新，草稿仍绑定原文本修订。

新调用、readiness 和执行包共用准确选择校验：缺版本、候选、原件、错配、非法范围或所选路线循环均阻断。CALL 只记录实际提交的直接输入，并保留原槽位对应；不把未执行路线或间接参考伪装成调用输入。

## 生成保护与物理退役

场／镜设计采纳及其历史正文退出；`production/acceptance` 不再接受 AV_EPISODE、AV_SCENE、AV_SHOT 决定，生成准备也不要求这些已取消的决定。素材方案认可、准确输入、原件选择、实际调用授权和失败幂等仍分别校验；读稿、切版、采用旧原件或执行清理均不授予付费权限。

`audiovisual_cleanup` 在准确清单和事务内清除旧视听专属字段、正文、作者映射以及视听关系的解释副本，独占设计决定删除。执行时重新检查头、历史和评论；若新增有效评论需要保留，整次删除拒绝。关系端点、路线、实际 Prompt、CALL 和原件不属于这些冗余字段。

历史组成仍须被真实调用定位，因此保留其准确修订标识和可执行事实，旧正文从载荷物理移除。清理凭据仅存原摘要、剩余载荷摘要、事实摘要和字段名，不存被删文字；恢复同时验证对象类型与载荷，不能借凭据改写身份或事实。迁移生效后，新写入或旧包恢复不能重新引入旧视听字段。

Schema 11 完整包携带统一关系身份／旧别名／迁移回执、清理凭据、当前工作稿及准确引用。恢复只进入空实例，实例配置中的 `audiovisual_reading_policy` 固定对象范围和已执行清理；普通增量发布不能用任务快照覆盖活库。具体删除范围和正式应用授权由实例项目负责。

回归：`test_audiovisual_reading.py` 覆盖状态归属、并发工作稿、评论阻断、事实篡改、旧格式再导入及空恢复；`ui_unification_requirements.test.cjs` 覆盖三部分、产物顺序、准确切版／链接和共用卡历史状态；`ui_material_independent.test.cjs` 覆盖旧版无定义或仅有真实调用。`shot_reading.test.cjs` 保留准确投影和旧评论／草稿端点保护。实例另提交真实浏览器和逐集叙事验收；测试不能证明声画效果。
