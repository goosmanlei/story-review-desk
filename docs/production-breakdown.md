# 视听制作：目的、关键状态与生成方案

顶部选择当前视听集，左侧选择当前场镜。每镜按叙事目的、关键状态、生成方案呈现；集场工作稿在悬停或聚焦时读取。所有制作内容原地维护，改镜头不新建父场或父集版本。

## 准确组成与内容

`AV_EPISODE.scenes`、`AV_SCENE.shots` 与需求归属使用当前对象的稳定地址；输入锁、准确故事版本和对象配对继续校验。旧制作地址只映射真实候选、原意见或明确退役说明，不能按最新稿冒充旧组成。

当前写入使用 `reading_contract: audiovisual-three-part-v1`。集场仅保存准确组成；镜头保存 `purpose`、`key_states` 和 `products`，另保留来源、既有时长与实际身份依赖。`purpose` 解释本镜给观众的新理解或感受，不由系统按动作模板生成。

`key_states` 是有独立素材准备需要的镜内时刻。每项含稳定 `id`、自然语言 `description` 与准确 `requirements` 引用；同一状态可关联多个需求，同一需求不能重复占据两个状态。需求须属于本镜对象，允许显式复用本镜较早设计下的准确需求；不能借另一镜需求。没有中间状态就不制造占位。

`products` 按真实制作顺序保存 `{label, requirement}`，页面按此顺序设 Tab，初入选择第一项，返回仅恢复本镜仍合法的选择。上游参考不自动成为产物。缺少准确需求、没有产物或没有模型方案分别显示具体空态。工程保持工程身份，通过共用卡读取 ZIP 等原件和交付要求，不冒充生成视频。

每个 Tab 直接显示当前方案或选定候选的参考、模型／参数和完整 Prompt。候选读取提交快照，历史缺口不借当前内容补写；没有制作版本按钮。

参考列表保留实际素材身份、候选、组成、哈希及裁切／时间范围。共用卡关闭后恢复镜头位置、产物选择和各自评论草稿，浏览不改变生成输入。

## 当前工作稿与准确反馈

`audiovisual_notes` 每集／场一行，`body` 最长三万字；读取随集场导航返回；`POST /api/production/working-note` 使用 `object_id` 和 `expected_etag` 防止覆盖并发更新。更新不产生设计修订或历史副本；不允许为镜头写这类工作稿。完整导出保存当前正文与更新时间。

叙事目的、状态描述、参数和 Prompt 沿原对象／修订／字段的文字锚点反馈。连续跨块和分段圈选保持准确端点，保存／刷新／关闭／重开不改绑。详见 [评论范围](comment-checklist.md#组合阅读中的准确文字范围)。已有 `production_reading`、`scene_reading` 是其他阅读入口的准确投影能力；视听镜卡不再据此建立动作对白或共同条件副本。准确 Prompt 和锁定剧本继续保存影片实际要表达的内容。

集评论计数覆盖该集准确组成与直接素材的定义、候选，含已关闭评论且去重；不混入无关上游或故事评论。来源按钮读准确故事场并高亮引用范围；来源缺失不回落同名或最新版。

## 素材关系与执行路线

实体、素材需求／原件与镜头关系统一为 `RELATION/business`，一对稳定端点一份当前描述。生成所需约束由作者融入完整 Prompt，提交时保存实际所用内容。旧 MATERIAL_RELATION 已退役，仅保留必要地址映射。

必需参考参与当前路线校验。可选参考由 enabled 决定；条件参考需明确判断条件；one_of 参考必须为其 group 选择 route。计划的 selected_routes 与 conditions 参与冻结定义。只检查当前执行路线的缺项和循环，不能让未选路线误阻断，也不能让描述关系自动提交输入。

`POST /api/production/material-route` 使用唯一操作 id、requirement_id、当前 `expected_content` 和既有路线字段。读取后在同一事务核对并发标记，修改唯一当前方案；重复同一载荷幂等，旧标记拒绝，不创建新版。

## 准确参考选择

小卡和 Prompt 标记通过原始有序输入槽位打开同一详情。直接参考可“选为方案参考”；间接参考只读，并指明其上游所有者，不能静默改写共享需求。浏览、比较、选择参考和实际采用互不推断。

`POST /api/production/shot-reference` 沿既有槽位协议选择准确 candidate、component_id 和可选 crop/range，并携带消费需求的 `expected_content`。input_key 校验原槽位，候选、文件与范围必须匹配；图像坐标归一化，音视频以秒计。

旧版号和 `baseline_id` 只为准确历史地址映射保留；新方案不建立版本。缺失或已退役输入明确拒绝，不能改用最新候选。

保存回执返回当前稳定地址、新的并发标记和准确槽位。下次修改重新取得该标记及 input_key；同一操作身份只能重发相同载荷。

消费小卡直接显示已保存的时间范围或已登记裁切。详情中的相同选择显示已保存，编辑后变为“保存修改 · 未保存”；放弃范围修改恢复已保存数值。编辑值按素材版本、候选和文件组成分别保留，切换只用于浏览，试听／预览组成不能作为原件保存。空数值先拒绝，其他范围校验继续由服务端负责；失败保留当前编辑值。

音视频参考的范围控件紧邻播放器。“试听已保存片段”直接使用此消费位置保存的准确版本、候选、组成及起止；调整后变为“试听未保存范围”，只有明确保存才推进生成输入。放弃恢复保存值，修改范围时暂停正在试听的旧范围。播放器的完整播放入口明确区分原件和预览，从文件起点播放全长；暂停控件表明当前播放的是已保存片段、未保存范围、评论选段还是完整文件。评论圈选与参考范围独立，试听参考不建立评论圈选，清除评论选段也不扩大参考试听。关闭、切换及读取失败沿原生命周期保护，不替换准确文件。选段终点另按真实媒体时间调度，避免仅靠低频 `timeupdate` 事件迟停。

一次保存只绑定发出请求时的消费方案和位置。响应推进该编辑会话的准确身份，但不会覆盖保存中继续输入的值或将已保存提示刷到另一候选。关闭时仍有请求就等待其结果，再回到原消费位置刷新；进入其他卡时先等待返回，不重绘新读卡。已切换页面或失效的原消费入口不会接收迟到刷新。选择成功仍须通过准确文件、输入锁、方法和谱系等生成准备条件。

回归入口为 `tests/shot_reference_loop.test.cjs`、`tests/media_location.test.cjs`、`tests/ui_unification_compatibility.test.cjs`、`tests/version_consolidation.test.cjs` 与 `tests/test_shot_references.py`；真实浏览器、实例版本与正式数据保护由实例任务留证。

替换原件而未再次提交范围时清除旧 crop/range，不能把另一候选的范围带入新原件。其他槽位不变；原地更新当前方案，真实调用和旧意见不变。同操作 ID 同载荷重试返回原结果，不同载荷拒绝。读取中切换、关闭或转工作区后，迟到响应不覆盖新对象。保存后等待弹窗历史返回再刷新，草稿仍绑定原文本修订。

新调用、readiness 和执行包共用准确选择校验：缺版本、候选、原件、错配、非法范围或所选路线循环均阻断。CALL 只记录实际提交的直接输入，并保留原槽位对应；不把未执行路线或间接参考伪装成调用输入。

## 生成保护与物理退役

所有逐对象审批及其历史正文退出；旧审批写入口不再提供，生成准备不要求决定或评论。准确输入、原件选择、实际调用授权和失败幂等仍分别校验；读稿、切版、采用旧原件或执行清理均不授予付费权限。

`audiovisual_cleanup` 在准确清单和事务内清除旧视听专属字段、正文、作者映射以及视听关系的解释副本，独占设计决定删除。执行时重新检查头、历史和评论；若新增有效评论需要保留，整次删除拒绝。关系端点、路线、实际 Prompt、CALL 和原件不属于这些冗余字段。

真实调用的必要上游内容已进入提交快照，旧集场镜全文与历史组成树退出活库。最小退役映射仅保存身份和摘要，不能还原旧全文。

Schema 13 完整包与空实例恢复采用 [当前制作与候选](material-versions.md) 契约。普通增量器不覆盖活库；有意删除与原地模型切换必须沿实例专门迁移和共享写入窗口执行。

回归：`test_audiovisual_reading.py` 覆盖状态归属、并发工作稿、评论阻断、事实篡改、旧格式再导入及空恢复；`ui_unification_requirements.test.cjs` 覆盖三部分、产物顺序、准确切版／链接和共用卡历史状态；`ui_material_independent.test.cjs` 覆盖旧版无定义或仅有真实调用。`shot_reading.test.cjs` 保留准确投影和旧评论／草稿端点保护。实例另提交真实浏览器和逐集叙事验收；测试不能证明声画效果。
