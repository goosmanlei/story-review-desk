# 从当前稿复核历史意见

故事结构与资料评论面板提供“历史意见复核”。未关闭数来自原评论账本，作者回应另行读取；有回应不等于已解决，缺少记录不等于未修改。原稿自己的意见继续在本稿列表，已有关联依据时可从原评论卡进入复核。

复核窗先展示准确原圈选，可查看作者回应、回应所针对的稿件、已登记的改动原文或图像，再回原意见选择关闭、重开或保留决定。当前正文、版本、章节与未提交草稿保持在底层；关闭窗口返回原阅读位置。圈选默认显示必要邻文，完整准确稿按需展开，不在干净正文加入历史标记。

结构回应从当前稿的真实父稿链读取，仍保存在原不可变修订。补充作者处理与准确修改依据使用普通 `GUIDANCE` 对象，格式 `comment-handling-v1`；不保存第二份评论状态，不调用创作工具或 runtime 目录。每项绑定原评论 ID、对象和修订、原圈选 SHA-256、回应稿、原决定与理由、来源哈希及准确内容锚点。结构补充依据不得改写已存在的回应。

后台通过 `python3 -m review_desk --instance INSTANCE import-comment-evidence FILE [--validate-only]` 校验和增量登记。批次先完整核验，再原子追加；相同内容幂等，已有同 ID 不同内容拒绝覆盖。沿统一对象、修订、依赖、导出和空库恢复契约保存。

`GET /api/comment-review?object_id=...&revision_id=...` 返回原评论与作者处理关系；`/api/comment-review/content` 以相同参数返回准确稿件。当前保留证据只认明确登记到当前修订的引用。回应稿后来被改写，或没有当前修订的证据时，界面明确未确认当前是否保留修改，不做相似句匹配。目标失效时保留意见和已有说明，拒绝换成最新稿。

关闭和重开继续使用 `PATCH /api/comments/{id}` 及 `expected_version`。同意见保存期间禁止重复操作；失败保留输入和原决定，版本冲突读取新决定，不覆盖它。未保存的评论编辑不进入作者处理结论。复核窗内 Esc 仅退出复核，不取消底层草稿。

自动契约检查在 `tests/test_comment_review.py`；故障夹具 `tests/comment_review_server.py` 只允许受管任务预览。真实页面另验当前→原圈选→回应→改动→原意见→返回、图像区域、Unicode 文字、草稿、失败和并发。正式实例只读复验，写入功能只在隔离库测试。
