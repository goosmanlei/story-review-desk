# 故事制作系统的素材关系与初始化架构

系统以一个故事实例为工作边界。故事内容、配置、实体、需求、版本和事件共同存放在实例数据库；基础软件不携带任何特定故事的数据。系统管理只确认规则与运行条件；故事资料在故事创作导入，故事设定和素材定义由各自工作区独立维护。

## 统一对象模型

| 对象 | 回答的问题 | 身份与变更规则 |
| --- | --- | --- |
| 来源资料 | 依据来自哪里 | 原始文件字节、来源身份、修订和 SHA；提取文本独立登记，保留原件 |
| 故事实体 | 它是谁或是什么 | 人物、地点、道具、声音主体、台词等可配置类型；永久 ID，不以显示名作身份 |
| 实体状态 | 故事中何时、处于什么条件 | 年龄、服饰、境遇、损坏、时辰、天气、位置等维度；绑定故事范围与修订 |
| 表现形式 | 要做成哪一种素材 | 身份母图、首级、尸身、人物信息卡、声音母版、场景空态、机位图、冻结状态图等 |
| 素材需求 | 为什么需要、用在哪里 | 来源证据、验收口径、复用范围、关联场集镜头；需求登记不等于文件产出 |
| 素材族与版本 | 现在具体使用哪个文件 | 族保持语义身份，版本固定文件、SHA、实际 Prompt、模型、父版本和审阅状态 |
| 工作对象与交付物 | 在制作的哪个环节消费它 | 镜头、预演、场、集、全剧输出分别冻结输入、审阅和计算分母 |

同一个人物的不同年龄、衣着、声音、信息卡与尸身共用人物实体身份，但各自拥有独立的表现、需求和资产版本。地点的空间布局、机位、时间和故事状态分开建模。道具的完整、损坏、持有者与位置，声音的音色、对白、环境底声与同步事件也采用相同结构。

## 基础素材与制作过程素材

素材管理提供两个视图，共用素材族、不可变版本、生产资料、审阅和用途卡。基础素材由实体、状态和素材需求组织；制作过程素材由当前镜头制作计划中的工作项组织，不为一张粗分镜虚构新故事实体。粗分镜、逐条对白、正式关键帧、Animatic、镜头视频和锁定清单均有各自的预期产物与实际版本。没有实际文件与登记证明时，预期产物保持未产出。

制作计划绑定当前场正文、镜头设计、精确素材输入、空间、关键帧策略、声音分支与剪辑余量。修改时仅新建受影响的工作及输出，未变化的工作和素材身份可以复用；历史设计、调用包和审阅证明保持原字节。源同步验证并保留完整过程对象闭包。工作步骤见 [镜头制作](shot-production.md)。

## 四种关系与两种时间

故事关系描述人物亲缘、社会身份、空间包含、物品归属等事实。状态与连续性关系说明同一实体如何变化。参考关系规定生成时可继承哪些特征、必须排除哪些特征。组合关系说明多个独立素材如何形成合成产物。

每条关系拥有独立 ID、方向、用途、继承与排除项、作用范围、证据和确认状态。证据分别使用 F（来源事实）、A（改编）、L（制作锁定）、U（未知）；AI 建议不自动成为确认事实。故事发生时间与观众看到信息的时点分别表达，涉及具体集、场、镜头时绑定永久身份及精确修订，不依赖 E01 等显示编号。

结拜关系不能作为血缘参考。即使存在血缘，也须单独说明是否允许借用一张获批亲属母图、只继承哪些相似特征，以及不能复制哪些身份特征。同人物母版、场景几何、服饰材质与声音节奏各自限定用途。纯确定性排版或合成可以记录组合血缘，但不能冒充模型看过或听过素材。

## 声明参考与实际参考

关系图记录制作规则。执行授权和候选登记都要再核对实际输入列表中的素材族、版本和 SHA，确认输入可下传、用途匹配、身份隔离成立、派生代际没有超限。没有精确版本记录时显示缺项；不能从相似外观、文件名、亲缘关系或当前配方推断历史参考。

生成结果最多连续修正两代，超限回到干净母版。人物身份母图不能将无亲缘人物图像作为身份附件。镜头仍须冻结场景空间与状态坐标、人物和道具；关系系统补充这些现有门禁，不替代它们。

修改已登记的实体、状态、表现或关系会生成新的关系修订和影响预览。已受影响的具体版本进入返修投影，实际引用这些版本的后续产物沿精确输入关系失效。既有 ReviewEvent 与权利事实保留原样。仅修改人物信息卡表现时，依赖该卡的合成结果受影响；未引用该卡的纯净镜头母版保持原有事实。

## 初始化与系统配置

“系统管理”分为使用与初始化、系统配置、数据与运行。配置按项目目标与规格、资料与证据、实体与素材体系、参考与连续性、流程与交付、审阅标准、AI 协作与界面七组组织。

资料通过网页粘贴／上传或项目内 Codex 显式导入。文件进入目录不会自动进入权威库。原始音视频只登记与保存，已有转写或字幕可另行导入；没有观察证据时保留 UNKNOWN，不自动发起转写、声音克隆或素材生成。

设定抽取任务冻结显式选定来源、当前 release、配置与已发布 graph。来源正文只发送所选集合，配置整体不可变；AI 结果进入独立 suggestions，不写两个业务草稿或 release。用户显式带入本模块 changes，经草稿 CAS、预览 hash、release CAS 和幂等事务确认。旧整图与初始化发布关闭；历史转交按原基线、当前、建议三方比较，已有目标草稿不可被替换。结果不明不自动重试模型调用。详细职责见 story-settings.md。

## 数据架构与部署

每个故事使用独立 PostgreSQL 18 服务、数据库角色、私有 Docker 网络及 named volume。数据库不开放宿主端口。活动 PGDATA 使用 Docker 管理卷；项目目录保存实例定位文件、受管媒体、源版本与事件的可恢复归档。移动项目需先导出并在新位置恢复，不能把复制项目目录当作复制活动数据库。

原始文档、配置、发布与事件保存不可变字节及 SHA；JSONB 和关系表只作可重建的查询投影。原始 JSON 的键顺序、空白和数值写法不会因投影而被重写。读取使用异步连接池和一致性事务，写入使用短事务、修订 CAS、请求幂等及追加事件。

已发布数据按发布身份缓存，实时状态按事件水位缓存；未提交数据不进入共享缓存。素材目录使用 SQL 过滤与稳定游标分页，摘要与完整详情分开获取，游标绑定发布、事件水位和筛选条件。维护任务持久排队，在受控工作器执行；成功必须有实际备份、校验或导出证据，恢复只写入新实例目录。

素材读模型更新在持有仓库写锁时复核运行投影，旧事件视图不能被标成新水位。读模型使用显式结构版本；版本过旧时从精确 release 完整重建。历史读缓存清理只允许 read_operational_objects、read_memberships、read_objects、read_sections、read_projection_versions 五表的非当前 release，绑定实例、运行期、Docker 卷、已核验备份 SHA、目标行摘要与当前行摘要；任何变化均拒绝执行。清理事务核对正式表与当前投影前后摘要，不能删除不可变历史来节省空间。维护心跳是原子临时文件，任务与回执仍为持久业务记录。

本地实例是唯一正式写入点。远端 Sites 展示同一精确软件提交及已验证导出，保持只读，不接收正式审阅、生成授权、源同步、初始化写入或维护命令，不托管原始录音。

PostgreSQL 新备份以逐行归档保存不可变表记录，避免将完整历史库拼接为单个字符串。清单记录格式、文件字节数和 SHA，归档仍保留原规范整体 SHA；恢复再验证原始业务行与媒体清退墓碑。旧 JSON 备份继续可读，不改写旧备份，恢复只进入新目录与独立数据卷。

## 当前故事迁移原则

迁移保留原始修订字节、事件顺序、永久身份、文件与 SHA、历史审阅意见、UNKNOWN 权利事实和已确认的内部使用范围。关系补录有明确源证据时才写入；无法证明的关系保持未知或提案。不同叙事修订的场集范围分别绑定，不把旧素材的场次显示编号静默映射到新的故事候选。

数据库切换以当前实例一致备份、隔离恢复、语义与事件核验、前端构建、真实 API 与浏览器回归、正式端口回读，以及同一提交的只读镜像验证为完成条件。
