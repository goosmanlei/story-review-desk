# 子路径与体验发布身份

本机根路径默认保持原行为。反代子路径时，应用进程设置 `REVIEW_BASE_PATH=/实例前缀`，代理保留完整请求路径，应用拒绝前缀外请求并规范跳转前缀目录。启动配置须与公共入口匹配，不从可伪造的转发头推断路径。

设置 `REVIEW_PUBLICATION_ID` 为准确、不可复用的发布身份后，HTML 提供该身份及路径，前端统一解析 API、静态文件、媒体、图标和附件 URL。`REVIEW_ENVIRONMENT=experience` 要求发布身份，并显示“体验环境，操作将在下次发布时重置”。业务数据中不保存主机凭据或当前部署身份。

浏览器持久数据按路径和身份隔离。访问新身份时清除当前路径旧发布的草稿、配置输入和页面位置；其他路径及历史根路径实例不被清除。已打开旧页面的 API 请求携带旧身份，服务端拒绝；所有写请求必须提供 `X-Review-Publication`，因此无头的旧客户端也不能跨发布写入。正常刷新及重启沿同身份保留交互。离线设备的副本不能主动擦除；服务端拒绝其跨版提交。

媒体保持原件哈希、Range、ETag 和压缩契约。可设置 `REVIEW_UPLOAD_RESERVE_BYTES`，服务器在流式上传前为所有并发上传累计预留空间，拒绝占用系统保留空间；默认根路径未设置此值时保留既有行为。

体验 API 必须有独立服务端凭据及实际授权。`REVIEW_POLISH_BUDGET_FILE` 指向业务重置之外的持久计数文件，`REVIEW_POLISH_MAX_ATTEMPTS` 是累计请求尝试上限。实际请求前先持锁增加计数，失败、超时和业务重置均不清零；文件只保存次数，不保存草稿或密钥。未设置体验调用预算时拒绝真实请求；这不是完整 API 验收。

认证、独立维护页、全量替换、资源预算、准确快照和发布回执由实例的发布工具负责。仅设置路径和身份不能证明部署成功；需要真实浏览器及前缀内写入、重启、两次发布与维护／恢复验证。HTTP 与存储边界测试见 `tests/test_deployment.py`、`tests/deployment.test.cjs`，完整系统回归仍需保留。
