# 审阅台整体框架（V1 起）

本系统从第一版即采用原审阅台的整体创作框架作为概念参照，但重新实现 Python 模块化单体；没有继承旧业务数据、运行状态、数据库或系统代码。六个业务域为故事创作（SOURCE/STORY/EPISODE/SCENE）、制作设定、素材管理、镜头制作、审阅协作、项目管理。界面常驻“制作思路、故事创作、生产制作、系统管理”。生产制作内设视听制作、实体管理、素材管理，承载已有制作数据的阅读、审阅与管理，具体契约见[制作模块说明](production.md)；入口开放不代表作品已经生成、获接受或完成。

“制作思路”是实例方法文档的只读展示，两个 Tab 分别说明故事创作与生产制作。文字与正式引用归实例 `content/production-approach.json`；系统 `approach.py` 和 `static/approach.js` 负责加载与安全文本渲染，文件随实例 Git 恢复，不进入业务账本或导出 Schema。无独立进度、统计或生产执行服务；旧首页没有专用持久数据，故无需数据迁移。`current_stage` 继续属于公共创作上下文。路由、恢复边界与完整清理清单见[制作思路说明](production-approach.md)。

`framework.py` 登记业务域、对象类型、阶段及工作区。`store.py` 为单一业务账本：对象稳定 ID、不可变修订、精确修订依赖、乐观版本；原始资料正文独立且不可原地覆盖。通用评论锚定精确对象修订、文本块和字符范围，资料评论兼容 `source_id`；旧资料评论在原位迁移并保留事件。对象后续换版不会把已有评论静默挪到新修订。后续故事、剧本、设定与制作稿使用同一账本及精确依赖，不另起平行存储系统。HTTP 与 CLI 访问同一个 Store 业务操作；`bundle.py` 完整导出业务账本、资料、评论、配置及素材，恢复先校验哈希与关联。异步任务/生产工作流尚未启用，不能称为已交付。

`configuration.py` 分 `SYSTEM`（润色模型、模型支持的推理强度、API Key 环境变量名、上下文预算）和 `PROJECT`（当前阶段、故事背景、创作背景、目标载体、受众、风格）；每次保存增加版本并保留配置事件。工作区是否已实现由 `framework.py` 内部登记，不是用户配置或权限开关。Schema 2 为旧 SYSTEM 配置增加强度；Schema 3 将旧版的“已启用工作区”从可编辑配置中移除，读取旧记录时忽略该字段，并为润色密钥环境变量名增加默认值 `OPENAI_API_KEY`。非推理模型填“不适用”，已配置推理模型迁移为 medium；服务端校验模型与强度组合，页面只呈现该模型可选值。模型列表为经过文档核对的显式目录，不代表本机密钥必有访问权。后续功能配置通过显式 schema 版本和迁移演进，未知字段或缺失迁移拒绝加载。系统配置页面只展示 SYSTEM/PROJECT，不再展示无操作价值的“本机运行”页。环境变量名属于可公开同步的配置；密钥值仅保留在服务容器环境中，不写业务库、不导出。

AI 润色先用 `polish.py` 建立可审阅参考并返回 SHA-256。页面已查看且意见、目标、锚点未变时复用该快照；服务端重新构建并要求哈希一致，变化返回 409，不能静默使用另一份参考。准确对象、完整圈选和意见优先，邻文围绕圈选节选；结构、分集保留其准确方向或改编依赖，普通措辞意见只记录依赖身份，涉及改编时才展开其正文。明确命名的比较稿标明仅供比较，不替换当前对象事实；泛称旧稿不能猜最新。项目阶段与背景只在当前意见需要时加入，当前审阅任务按目标类型表达。预算是 `len(canonical(context))` 的 Unicode 字符数，包括元数据、背景、完整圈选、意见与格式；必要内容容纳不了时明确拒绝，不截断圈选。`budget.used` 与真实请求 `input` 使用同一序列化内容。建议不自动保存，须人工采用到草稿后另行提交；采用后清除旧参考。凭据从配置指定环境变量读取，默认 `OPENAI_API_KEY`；请求 `store=false`，推理模型按配置传 `reasoning.effort`，非推理模型不传。

制作参数的可评论文本由 `review_text.py` 统一投影；制作记录读取与评论锚点校验使用相同的 JSON 排序、数值格式和重复提示词处理规则。原始参数仍留在不可变修订中，展示投影不迁移数据或改变导出格式。
