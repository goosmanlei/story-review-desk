# 审阅台整体框架（V1 起）

本系统从第一版即采用原审阅台的整体创作框架作为概念参照，但重新实现 Python 模块化单体；没有继承旧业务数据、运行状态、数据库或系统代码。六个业务域为故事创作（SOURCE/STORY/EPISODE/SCENE）、故事设定、素材管理、全剧制作、审阅协作、项目管理。界面常驻“当前工作、故事创作、故事设定、素材管理、全剧制作、系统管理”；仅资料采编和系统配置为 V1 可操作区，其余明确标示“待开放”。

`framework.py` 登记业务域、对象类型、阶段及工作区。`store.py` 为单一业务账本：对象稳定 ID、不可变修订、精确修订依赖、乐观版本；原始资料正文独立且不可原地覆盖。通用评论锚定精确对象修订、文本块和字符范围，资料评论兼容 `source_id`；旧资料评论在原位迁移并保留事件。对象后续换版不会把已有评论静默挪到新修订。后续故事、剧本、设定与制作稿使用同一账本及精确依赖，不另起平行存储系统。HTTP 与 CLI 访问同一个 Store 业务操作；`bundle.py` 完整导出业务账本、资料、评论、配置及素材，恢复先校验哈希与关联。异步任务/生产工作流尚未启用，不能称为已交付。

`configuration.py` 分 `SYSTEM`（润色模型、上下文预算、已启用工作区）和 `PROJECT`（当前阶段、故事背景、创作背景、目标载体、受众、风格）；每次保存增加版本并保留配置事件。后续功能配置通过显式 schema 版本和迁移演进，未知字段或缺失迁移拒绝加载。`LOCAL` 仅运行端口和 API 密钥等进程环境，不写业务库、不导出。系统配置页面已经可编辑 SYSTEM/PROJECT，并展示 LOCAL 的非敏感状态。

AI 润色分两步：先用 `polish.py` 建立可审阅上下文并返回 SHA-256，再由用户发起请求；服务端重新计算并要求哈希一致。上下文含评论草稿、原文圈选、附近段落、当前资料全文（受预算约束）、其他已收录版本、各资料来源与修订、故事/创作背景、创作阶段、载体/受众/风格。未知信息标 `UNKNOWN`，不臆造。远端建议不自动保存；用户采用到草稿后才可提交。凭据来自本机 `OPENAI_API_KEY`，请求使用 `store=false`。
