# 实体与素材小卡、分组和分页

管理页先凭业务编号、名称和必要状态找对象，再在共用大卡中审阅。编号沿用 `business_codes.py` 的持久分配，不新增编号体系；普通进入仍使用现有“最大有真实候选版本／最新候选”策略，准确链接与手动选择优先。浏览和翻页不写采纳、采用或生成决定。

## 共用入口与点击

| 入口 | 实现与行为 |
| --- | --- |
| 实体管理 | `management-cards.js` 的 `entitySmallCard` 复用 `production.js` 的 `reviewSmallCard`；按实体身份打开 `openUnifiedMaterial` |
| 素材管理 | 同文件的 `loadMaterialManagement` 复用 `materialSmallCard`；打开同一素材身份的大卡 |
| 制作拆解与镜头制作 | `production-breakdown.js` 的逐镜素材列表复用 `materialSmallCard`；已有选定版本／候选时携带该版准确记录引用，未明确选择时使用默认策略 |
| 大卡左侧实体区底部 | `unified-cards.js`、`entity-review.js` 的状态素材列表复用同小卡；只切换同卡右侧，不叠层，保留实体、状态、阅读位置和草稿 |
| 无实体归属的大卡 | `renderUnifiedModels` 的素材列表复用同小卡；普通点击打开准确素材大卡 |
| 引用及叠层阅读 | 准确参考按钮保留原引用、修订、素材版本／候选；完整卡复用 `openUnifiedMaterial`，准确来源／原方案／原图继续使用相应引用阅读器 |
| 关系图及状态按钮 | 沿用关系图节点与状态选择的专用控件，分别叠开实体／切换状态，不把它们改成管理网格 |

`openUnifiedMaterial` 保存外层状态、评论面板和 URL，关闭后恢复外层，`openReviewDialog` 恢复焦点与滚动。管理页列表仍留在原 DOM，因此打开／关闭、素材切换及评论定位不重置筛选或分页。准确实体、状态、修订、素材、版号及候选都需校验；错误目标明确拒绝，不能默认替换。下层迟到读取等待上层关闭后才能激活；关闭或工作区变化后的响应丢弃。列表筛选响应另核对请求号与工作区加载身份。

小卡含独立编号行、名称、必要类型／媒体信息，名称完整文本可访问。已有图像使用真实原件缩略图，其他媒体或缺失项使用类型图标。实体显示“完整状态 N 个”和“未采纳／已采纳／需重新采纳”，图标同时提供可访问名称与提示。它们是只读信息。

## 权威读取和合并

`ui_projection.py` 的实体索引读取当前实体头，完整状态数直接使用大卡同一 `entity_review.full_states` 列表，按状态身份去重；历史保留、修订和候选不增加当前完整状态数。采纳由真实最新决定与当前范围比较：有效完整方案或内容采纳显示已采纳；原采纳范围失效显示需重新采纳；无采纳或已取消显示未采纳。真实结果是否存在不参与采纳推断。

`list_associations.entity_locations` 合并三类准确事实，并在响应保留原记录／来源／范围作为证据：实体本体和所属状态的分集正文来源；场检查及镜头记录明确列出的 entities、states、occurrences；实体或状态为 subject 的 occurrence／applicability 关系。状态通过准确 entity 引用归属，场镜位置由 `production_breakdown.location` 读取准确父级。每个实体只有一张卡；匹配多个状态、镜头或来源只增加证据，不增加身份。名称关键词和同场其他对象不产生关联。

`material_entries` 先沿现有 canonical_id 合并需求与原件身份，保留无需求历史原件；`material_uses` 再合并当前有效方案的有序准确输入、历史实际 CALL 的原始输入，以及明确的采用／适用关系。实际输入使用原调用绑定需求的准确范围，不能拿当前方案补写历史。素材挂载、适用、准确状态覆盖及状态的明确正文来源保留原有事实；父剧／集／场不自动扩展为所有子场镜。

素材在每个真实场分组出现一次，同场多镜、多状态及多个证据均按“组身份＋素材身份”去重；跨场仍打开同一素材。只有集关联的条目留在“集素材”，剧或输入锁范围留在“全剧素材”，无可定位集场且无剧范围的条目留在“未关联集场”。同时确有不同范围的素材可出现在相应各组。筛选后的 `total` 是唯一素材数，`display_total` 是实际分组展示项数，版本、候选和文件不计新素材。

集选项来自已登记且有有效业务编号的 EPISODE 头，仅显示 E 编号；场选项来自准确关联，仅显示 S 编号。切集清理原场选择，不依赖制作拆解当前输入锁的导航范围。实体类型、搜索、采纳筛选与集场组合；素材媒体、生成结果及搜索继续组合。所有筛选与每页行数变更回第一页。

## 三列基准分页与响应式

两个管理页共用 `groupedCardPage` 与 `reviewPagination`，分页在列表底部。每组独立起行，组行数为 `ceil(项数/3)`；标题及间距不计行，末行留空仍计一行。默认每页 10 行，提供 5／10／20／50 行选项，默认最多 30 个展示项。按稳定分组及组内编号／身份排序切页，续组仍显示标题，结果收缩时钳制到有效页，空结果保留禁用的第 1／1 页。

CSS 只重排当前页的集合：常规桌面三列，宽度不足降两列或一列，基准页集合不随视口改变。大卡内部和逐镜侧栏保持其现有可用宽度和单列小卡，不强制三列。行数提示说明以三列计算。制作拆解导航、侧栏扩展、媒体分类及选定候选后生产流不在此改造范围。

`tests/test_grouped_management.py` 核对身份、来源、状态、采纳、特殊归属与准确实体；`grouped-cards.test.cjs` 核对分组末行、跨页续组、遍历及钳制；共同界面用例核对准确版本、目标、分页记忆和迟到响应。真实浏览器证据、双仓候选与服务恢复步骤由故事项目的 `production/small-cards/` 保存，自动检查不能代替页面验收。
