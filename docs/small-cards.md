# 实体与素材小卡、分组和分页

管理页凭业务编号、名称和必要状态找对象，再在共用大卡中审阅当前内容与真实候选。编号持久分配，准确链接和手动选择优先；浏览、翻页不写采用或调用。

## 共用入口与点击

| 入口 | 实现与行为 |
| --- | --- |
| 实体管理 | `management-cards.js` 的 `entitySmallCard` 复用 `unified-cards.js` 的 `reviewSmallCard`；按实体身份打开 `openUnifiedMaterial` |
| 素材管理 | 同文件的 `loadMaterialManagement` 复用 `materialSmallCard`；打开同一素材身份的大卡 |
| 视听制作 | `production-breakdown.js` 的逐镜素材列表复用 `materialSmallCard`；已有选定版本／候选时携带该版准确记录引用，未明确选择时使用默认策略 |
| 故事相关制作 | `screenplay.js` 的实体、状态、需求按引用修订打开同一完整卡；视听场继续进入完整视听制作，关系和原件继续沿各自准确引用阅读器 |
| 大卡左侧实体区 | `unified-cards.js`、`entity-review.js` 的实体自身需求与状态素材列表复用同小卡；只切换同卡右侧，不叠层，保留实体、状态、阅读位置和草稿 |
| 镜头等制作来源的大卡 | 左侧显示准确来源、剧情依据与同来源需求列表；点击需求小卡切换右侧准确方案，不必关闭重开 |
| 引用及叠层阅读 | 准确参考按钮保留原引用、修订、素材版本／候选；完整卡复用 `openUnifiedMaterial`，准确来源／原方案／原图继续使用相应引用阅读器 |
| 关系图及状态按钮 | 沿用关系图节点与状态选择的专用控件，分别叠开实体／切换状态，不把它们改成管理网格 |

`openUnifiedMaterial` 保存外层状态、评论面板和 URL，关闭后恢复外层，`openReviewDialog` 恢复焦点与滚动。管理页列表仍留在原 DOM，因此打开／关闭、素材切换及评论定位不重置筛选或分页。准确实体、状态、修订、素材、版号及候选都需校验；错误目标明确拒绝，不能默认替换。下层迟到读取等待上层关闭后才能激活；关闭或工作区变化后的响应丢弃。列表筛选响应另核对请求号与工作区加载身份。

完整卡叠在故事页面时，底层工作区和集场保持不变；卡片拥有前景评论、圈选及草稿范围，关闭处理保存完卡内草稿后才恢复原场。原场与嵌套卡的草稿分别保存，引用预览不覆盖原场草稿元数据。共用弹窗同时恢复资料、结构、剧本各自的正文滚动容器。

小卡标题同行显示类型图标、名称和业务编号，省略重复的类型文字与独占编号行。图标提供可访问名称和提示，长标题可从完整名称提示取得；编号和底部信息不被截断。已有图像保留真实原件缩略图。实体底部显示“状态 N 个 · 素材 M 个”；素材底部显示“候选 M 个”，不重复显示有无生成结果。它们是只读信息。

## 需求来源与准确历史

左侧的来源名称和正文回答“为何需要这份素材”；剧情依据用于回看原文；需求小卡用于在同一来源内比较用途；右侧的当前方案与候选用于审阅准确内容。实体自身需求列在基础信息后，状态需求列在所属状态内。镜头需求按其准确 `scope` 归组，只列直接属于该镜头的需求，不按入画人物或间接适用关系归组。

实体级需求进入列表、素材计数和卡片投影，评论分别绑定实体、状态、准确需求或原件。没有整实体审批范围；准备只检查实际消费方案的必要输入。

历史原件依次检查准确需求来源、实际调用、状态覆盖和 subject 引用。退役占位或空来源不能遮蔽其他有效准确证据；无证据时保留未知说明，不猜测同名对象。当前需求和独立状态仍可查看，旧候选读取提交快照，关联用途复用中文标题和持久业务编号。

同来源切换按需读取，并为每项需求保留所选当前方案／候选、评论目标、圈选及草稿；返回恢复原准确 URL。请求完成时仍须属于同一卡片和来源，否则丢弃响应。参考小卡、Prompt 引用、两类管理页、故事相关制作及深链共用这一准确引用契约。

## 权威读取和合并

`ui_projection.py` 的实体索引读取当前实体头，完整状态数直接使用大卡同一 `entity_review.full_states` 列表，按状态身份去重；历史保留、修订和候选不增加当前完整状态数。实体素材数从同一真实关联集合按规范素材身份去重，同一素材跨状态、分组、候选或文件仍只算一次。大卡章节名为“实体状态”，内部 `full_states`、状态身份及历史清理契约不变。

`list_associations.entity_locations` 合并三类准确事实，并在响应保留原记录／来源／范围作为证据：实体本体和所属状态的分集正文来源；场检查及镜头记录明确列出的 entities、states、occurrences；实体或状态为 subject 的 occurrence／applicability 关系。状态通过准确 entity 引用归属，场镜位置由 `production_breakdown.location` 读取准确父级。每个实体只有一张卡；匹配多个状态、镜头或来源只增加证据，不增加身份。名称关键词和同场其他对象不产生关联。

`material_entries` 先沿现有 canonical_id 合并需求与原件身份，保留无需求历史原件；`material_uses` 再合并当前有效方案的有序准确输入、历史实际 CALL 的原始输入，以及明确的采用／适用关系。实际输入使用原调用绑定需求的准确范围，不能拿当前方案补写历史。素材挂载、适用、准确状态覆盖及状态的明确正文来源保留原有事实；父剧／集／场不自动扩展为所有子场镜。

素材在每个真实场分组出现一次，同场多镜、多状态及多个证据均按“组身份＋素材身份”去重；跨场仍打开同一素材。只有集关联的条目留在“集素材”，剧或输入锁范围留在“全剧素材”，无可定位集场且无剧范围的条目留在“未关联集场”。同时确有不同范围的素材可出现在相应各组。筛选后的 `total` 是唯一素材数，`display_total` 是实际分组展示项数，版本、候选和文件不计新素材。

两管理页的主要范围为准确视听集／场。`production_scope.graph` 从当前 AV_EPISODE 的准确 `scenes`、各场准确 `shots` 建立目录，不把 `sources` 反向映射为制作范围；拆场和跨多个故事场都沿同一父子链读取。目录包含空场，不按搜索结果裁掉集场选项。镜头的产物和关键状态需求沿该镜头固定的准确引用进入范围，即使需求自身仍指向较早镜头修订，也不丢失当前编排的集场归属；递归输入读取所选方案，不能借当前头替换历史。实体从准确场镜的实体、状态、出现关系、连续性背景与具体输入的实体归属汇总；素材从准确位置需求、具体状态准备、明确适用／采用以及方案输入和原调用输入汇总。只沿实际声明的有效计划输入递进，不自动展开所有素材祖先；未选路线保留为具体消费方案的备选，不视为真实调用。统一业务关系只有准确适用范围是具体位置或明确使用的状态时才供该位置评估；全局实体备选不会借实体首个故事来源进入某场。

集场筛选复用平铺单选按钮，提供“全部集／全部场”；场选择同时固定所属准确集版本。搜索、类型、媒体和结果条件继续取交集，改变范围或筛选回第一页，分页仍按四列基准行计算。两页共享 URL 的 `production_scope_episode`、`production_scope_revision`（视听集准确修订）和 `production_scope_scene`，页内其他筛选及分页各自保留。从已经完成读取的视听场进入管理页沿同一准确范围，返回保留原场、镜头和阅读位置；版本变化不恢复另一版镜头。迟到读取继续受请求号及工作区生命周期保护。

管理接口以 `scope=av` 读取当前视听集场范围，来源仍保留准确故事版本。失效历史制作地址明确退役，不能把当前组成冒充旧版；无定位普通入口读取当前范围。源文位置不能当作实际制作使用位置。

这份投影只读，不改变原件、关系、评论、质量判断或调用授权。准确卡片和用途意见沿原共同入口读取；计划拟用、原件选定和真实调用分别成立。

`material_plans.card_counts` 按真实候选身份计数；重复元数据、文件组成及无原件调用不增候选。当前需求只保留一份方案，小卡只展示候选数量。

`/api/production/materials`、素材投影和 `material_card_counts` 提供候选数量。当前模型中旧 `version_count`／number 仅供兼容读取，不是业务版本，也不在界面展示。

## 用名称、编号和来源动作查找

`navigation_search.py` 维护后端搜索字段；实体列表使用同一投影的 `entity_search_fields`。查询与字段统一全角／半角、大小写和连续空白，中文按连续文本匹配。完整的 M、EN、ST、ASH、AS、AE 编号按字段精确匹配，不将 M262 当作 M2624。内部对象 ID、原始 JSON、生成 Prompt 与参考输入的递归展开不参与搜索。

素材搜索包括其持久 M 编号和自身的名称、描述、用途；直接来源的编号、名称与别名也可检索。直接来源为镜头时，补入该准确修订的叙事目的、起止动作与表演；实体状态说明中转述的其他镜头动作不充当来源动作。实体搜索包括自身及所属状态的 EN／ST 编号、名称、别名、描述与已登记事实、选择和未知项；文字命中不创造新的用途关系。两类搜索均与原有集、场、媒体或结果条件取交集。

有搜索词且未限定集场时，素材列表按独立素材身份展示一次，卡下可展开全部真实位置用途。限定集或场，以及无搜索词的普通浏览，继续按位置分组，同素材跨场保留展示。接口 `total` 仍为唯一素材数，`display_total` 仍为真实分组项数；界面的展示项数按当前目的计算，身份查找显示 `total`，位置浏览显示 `display_total`。用途数按真实分组计数，不是文件、候选或输入次数；不删除或重写关系。用途中的重复正文引用只在相同集、场和修订内合并高亮块，不跨修订混合；名称从准确正文来源取得。展开状态在本标签页刷新后恢复。

集场筛选与用途入口显示已有内容名和持久 S 编号。历史剧本版本由版本控件和准确来源修订区分；视听场保留独立 AS 编号。镜头显示 ASH 编号与动作名，移除其旧位置前缀；需求沿同一方式命名，数据标题和编号不改写。

状态关联镜头及需求来源打开当前完整镜头设计和已有素材；共用渲染器与叠层导航，不提供制作设计版本选择。关闭时恢复外层草稿、URL 和阅读位置。故事依据仍打开准确文字剧本版本。

显式未知结构修订、剧本版本、集或场不使用普通入口的默认目标，页面说明不可用并提供可选目标；失效页不开放意见入口。用户主动选择可用目标后同步地址、标题和意见对象。无定位参数的普通入口和主动版本切换仍选择合理的首集、首场或当前结构稿。

`test_navigation_search.py`、`test_navigation_projection.py`、`readable-navigation.test.cjs` 与既有路由测试覆盖明确字段、直接来源、筛选交集、历史完整设计、目的分组、失败版本及迟到响应。实际页面操作和实例交付证据由故事项目任务回执记录。

## 四列基准分页与响应式

两个管理页共用 `groupedCardPage` 与 `reviewPagination`，分页在列表底部。每组独立起行，组行数为 `ceil(项数/4)`；标题及间距不计行，末行留空仍计一行。默认每页 10 行，提供 5／10／20／50 行选项，默认最多 40 个展示项。按稳定分组及组内编号／身份排序切页，续组仍显示标题，结果收缩时钳制到有效页，空结果保留禁用的第 1／1 页。

CSS 只重排当前页的集合：常规桌面四列，宽度不足降两列或一列，基准页集合不随视口改变。大卡内部和逐镜侧栏保持其现有可用宽度和单列小卡，不强制四列。行数提示说明以四列计算。视听制作导航、侧栏扩展、媒体分类及选定候选后生产流不在此改造范围。

`tests/test_card_counts.py` 核对版数、候选身份、重复关联、失败调用及未知值；`tests/test_grouped_management.py` 核对身份、来源、状态、特殊归属与准确实体；`grouped-cards.test.cjs` 核对分组末行、跨页续组、遍历及钳制；共同界面用例核对准确版本、目标、分页记忆和迟到响应。真实浏览器证据、双仓候选与服务恢复步骤由故事项目的 `production/small-cards/` 与 `production/entity-cards/` 保存，自动检查不能代替页面验收。
