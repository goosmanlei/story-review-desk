# 实体与素材小卡、分组和分页

管理页先凭业务编号、名称和必要状态找对象，再在共用大卡中审阅。编号沿用 `business_codes.py` 的持久分配，不新增编号体系；普通进入仍使用现有“最大有真实候选版本／最新候选”策略，准确链接与手动选择优先。浏览和翻页不写采纳、采用或生成决定。

## 共用入口与点击

| 入口 | 实现与行为 |
| --- | --- |
| 实体管理 | `management-cards.js` 的 `entitySmallCard` 复用 `unified-cards.js` 的 `reviewSmallCard`；按实体身份打开 `openUnifiedMaterial` |
| 素材管理 | 同文件的 `loadMaterialManagement` 复用 `materialSmallCard`；打开同一素材身份的大卡 |
| 视听制作 | `production-breakdown.js` 的逐镜素材列表复用 `materialSmallCard`；已有选定版本／候选时携带该版准确记录引用，未明确选择时使用默认策略 |
| 大卡左侧实体区 | `unified-cards.js`、`entity-review.js` 的实体自身需求与状态素材列表复用同小卡；只切换同卡右侧，不叠层，保留实体、状态、阅读位置和草稿 |
| 镜头等制作来源的大卡 | 左侧显示准确来源、剧情依据与同来源需求列表；点击需求小卡切换右侧准确方案，不必关闭重开 |
| 引用及叠层阅读 | 准确参考按钮保留原引用、修订、素材版本／候选；完整卡复用 `openUnifiedMaterial`，准确来源／原方案／原图继续使用相应引用阅读器 |
| 关系图及状态按钮 | 沿用关系图节点与状态选择的专用控件，分别叠开实体／切换状态，不把它们改成管理网格 |

`openUnifiedMaterial` 保存外层状态、评论面板和 URL，关闭后恢复外层，`openReviewDialog` 恢复焦点与滚动。管理页列表仍留在原 DOM，因此打开／关闭、素材切换及评论定位不重置筛选或分页。准确实体、状态、修订、素材、版号及候选都需校验；错误目标明确拒绝，不能默认替换。下层迟到读取等待上层关闭后才能激活；关闭或工作区变化后的响应丢弃。列表筛选响应另核对请求号与工作区加载身份。

小卡标题同行显示类型图标、名称和业务编号，省略重复的类型文字与独占编号行。图标提供可访问名称和提示，长标题可从完整名称提示取得；编号和底部信息不被截断。已有图像保留真实原件缩略图。实体底部显示“状态 N 个 · 素材 M 个 · 未采纳／已采纳／需重新采纳”；素材底部显示“版本 N 个 · 候选 M 个”，不重复显示有无生成结果。它们是只读信息。

## 需求来源与准确历史

左侧的来源名称和正文回答“为何需要这份素材”；剧情依据用于回看原文；需求小卡用于在同一来源内比较用途；右侧的版本、候选与制作方案用于审阅准确内容。实体自身需求列在基础信息后，状态需求列在所属状态内。镜头需求按其准确 `scope` 归组，只列直接属于该镜头的需求，不按入画人物或间接适用关系归组。

实体级需求进入列表、素材计数和卡片投影，但不扩入既有整实体采纳的 `decision_scope` 或准备检查。实体采纳按钮认可原有基础信息、关系、状态及状态方案；实体自身需求独立审阅，浏览不迁移历史认可或采用。

历史原件依次检查准确需求来源、实际调用、状态覆盖和 subject 引用。退役占位或空来源不能遮蔽其他有效准确证据；无证据时保留未知说明，不猜测同名对象。准确旧需求、状态及素材版本仍可查看，关联用途复用中文标题和持久业务编号。

同来源切换按需读取，并为每项需求保留所选版本／候选、评论目标、圈选及草稿；返回恢复原准确 URL。请求完成时仍须属于同一卡片和来源，否则丢弃响应。参考小卡、Prompt 引用、两类管理页、故事相关制作及深链共用这一准确引用契约。

## 权威读取和合并

`ui_projection.py` 的实体索引读取当前实体头，完整状态数直接使用大卡同一 `entity_review.full_states` 列表，按状态身份去重；历史保留、修订和候选不增加当前完整状态数。采纳由真实最新决定与当前范围比较：有效完整方案或内容采纳显示已采纳；原采纳范围失效显示需重新采纳；无采纳或已取消显示未采纳。真实结果是否存在不参与采纳推断。实体素材数从同一真实关联集合按规范素材身份去重，同一素材跨状态、分组、候选或文件仍只算一次。大卡章节名为“实体状态”，内部 `full_states`、状态身份及历史清理契约不变。

`list_associations.entity_locations` 合并三类准确事实，并在响应保留原记录／来源／范围作为证据：实体本体和所属状态的分集正文来源；场检查及镜头记录明确列出的 entities、states、occurrences；实体或状态为 subject 的 occurrence／applicability 关系。状态通过准确 entity 引用归属，场镜位置由 `production_breakdown.location` 读取准确父级。每个实体只有一张卡；匹配多个状态、镜头或来源只增加证据，不增加身份。名称关键词和同场其他对象不产生关联。

`material_entries` 先沿现有 canonical_id 合并需求与原件身份，保留无需求历史原件；`material_uses` 再合并当前有效方案的有序准确输入、历史实际 CALL 的原始输入，以及明确的采用／适用关系。实际输入使用原调用绑定需求的准确范围，不能拿当前方案补写历史。素材挂载、适用、准确状态覆盖及状态的明确正文来源保留原有事实；父剧／集／场不自动扩展为所有子场镜。

素材在每个真实场分组出现一次，同场多镜、多状态及多个证据均按“组身份＋素材身份”去重；跨场仍打开同一素材。只有集关联的条目留在“集素材”，剧或输入锁范围留在“全剧素材”，无可定位集场且无剧范围的条目留在“未关联集场”。同时确有不同范围的素材可出现在相应各组。筛选后的 `total` 是唯一素材数，`display_total` 是实际分组展示项数，版本、候选和文件不计新素材。

集场筛选复用平铺按钮，单选且可换行，提供“全部集／全部场”；键盘 Tab 聚焦，Enter 或空格选择。集选项来自已登记且有有效业务编号的 EPISODE 头，仅显示 E 编号；场选项来自准确关联，显示 S 编号和已有内容名称。切集清理原场选择，不依赖视听制作当前输入锁的导航范围。实体类型、搜索、采纳筛选与集场组合；素材媒体、生成结果及搜索继续组合。所有筛选与每页行数变更回第一页。

`material_plans.card_counts` 读取已登记制作版本与候选身份。版本按规范素材身份和真实版号去重，包括没有候选的方案；候选按各准确版本内 `candidate_id` 去重，再跨版本汇总。文件组成、重复修订或失败调用不新增候选。已登记无候选显示 0；缺少登记显示“版本未登记 · 候选未登记”，不从修订数量或文件猜测。

`/api/production/materials` 的条目与拆解 `material_groups` 含 `version_count`、`candidate_count`；实体和素材详细响应的 `material_card_counts` 以素材身份为键；通用索引同名映射供兼容入口使用。镜头参考槽也提供这两个总量字段。它们独立于当前浏览版以及槽位的所选 `Vn Cn`；`V2 C2` 是第二版／第二候选的位置，不代表总量。旧调用方缺失字段时显示未登记。当前字段只是增补的只读投影，不改变准确引用或写入请求。

## 用名称、编号和来源动作查找

`navigation_search.py` 维护后端搜索字段；实体列表使用同一投影的 `entity_search_fields`。查询与字段统一全角／半角、大小写和连续空白，中文按连续文本匹配。完整的 M、EN、ST、ASH、AS、AE 编号按字段精确匹配，不将 M262 当作 M2624。内部对象 ID、原始 JSON、生成 Prompt 与参考输入的递归展开不参与搜索。

素材搜索包括其持久 M 编号和自身的名称、描述、用途；直接来源的编号、名称与别名也可检索。直接来源为镜头时，补入该准确修订的叙事目的、起止动作与表演；实体状态说明中转述的其他镜头动作不充当来源动作。实体搜索包括自身及所属状态的 EN／ST 编号、名称、别名、描述与已登记事实、选择和未知项；文字命中不创造新的用途关系。两类搜索均与原有集、场、媒体、结果或采纳条件取交集。

有搜索词且未限定集场时，素材列表按独立素材身份展示一次，卡下可展开全部真实位置用途。限定集或场，以及无搜索词的普通浏览，继续按位置分组，同素材跨场保留展示。接口 `total` 仍为唯一素材数，`display_total` 仍为真实分组项数；界面的展示项数按当前目的计算，身份查找显示 `total`，位置浏览显示 `display_total`。用途数按真实分组计数，不是文件、候选或输入次数；不删除或重写关系。用途中的重复正文引用只在相同集、场和修订内合并高亮块，不跨修订混合；名称从准确正文来源取得。展开状态在本标签页刷新后恢复。

集场筛选与用途入口显示已有内容名和持久 S 编号。历史剧本版本由版本控件和准确来源修订区分；视听场保留独立 AS 编号。镜头显示 ASH 编号与动作名，移除其旧位置前缀；需求沿同一方式命名，数据标题和编号不改写。

状态关联镜头及镜头需求来源可打开完整设计与已有素材方案。完整镜头卡复用逐镜渲染器、统一大卡、准确读取和原有叠层历史，不建立第二套路由。设计版本选择读取所选修订；失败恢复仍显示的版本，关闭或较新选择后的迟到响应不能替换当前对象。外层草稿、展开、版本、URL 和阅读位置沿原机制恢复。快速剧情依据预览继续读取准确正文；完整镜头的“故事依据”打开整场并高亮准确块。

显式未知结构修订、剧本版本、集或场不使用普通入口的默认目标，页面说明不可用并提供可选目标；失效页不开放意见入口。用户主动选择可用目标后同步地址、标题和意见对象。无定位参数的普通入口和主动版本切换仍选择合理的首集、首场或当前结构稿。

`test_navigation_search.py`、`test_navigation_projection.py`、`readable-navigation.test.cjs` 与既有路由测试覆盖明确字段、直接来源、筛选交集、历史完整设计、目的分组、失败版本及迟到响应。实际页面操作和实例交付证据由故事项目任务回执记录。

## 四列基准分页与响应式

两个管理页共用 `groupedCardPage` 与 `reviewPagination`，分页在列表底部。每组独立起行，组行数为 `ceil(项数/4)`；标题及间距不计行，末行留空仍计一行。默认每页 10 行，提供 5／10／20／50 行选项，默认最多 40 个展示项。按稳定分组及组内编号／身份排序切页，续组仍显示标题，结果收缩时钳制到有效页，空结果保留禁用的第 1／1 页。

CSS 只重排当前页的集合：常规桌面四列，宽度不足降两列或一列，基准页集合不随视口改变。大卡内部和逐镜侧栏保持其现有可用宽度和单列小卡，不强制四列。行数提示说明以四列计算。视听制作导航、侧栏扩展、媒体分类及选定候选后生产流不在此改造范围。

`tests/test_card_counts.py` 核对版数、候选身份、重复关联、失败调用及未知值；`tests/test_grouped_management.py` 核对身份、来源、状态、采纳、特殊归属与准确实体；`grouped-cards.test.cjs` 核对分组末行、跨页续组、遍历及钳制；共同界面用例核对准确版本、目标、分页记忆和迟到响应。真实浏览器证据、双仓候选与服务恢复步骤由故事项目的 `production/small-cards/` 与 `production/entity-cards/` 保存，自动检查不能代替页面验收。
