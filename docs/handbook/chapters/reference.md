# 术语、实现索引与设计决策

## 术语速查

| 术语 | 简明解释 |
| --- | --- |
| objectId | 永久业务对象身份 |
| revisionId | 对象的一份不可变内容 |
| expectedVersion | 写入前预期的对象计数，用于 CAS |
| operationId | 一次请求意图及可查询回执的身份 |
| runtimeEpoch | 实例运行期，阻止旧页面误写恢复后的状态 |
| basis | 当前读取／建议实际使用的版本依据 |
| adopted head | 已采用内容指针，与草稿头独立 |
| provenance | 来源或业务证明，随精确修订保存 |
| INPUT_LOCK | 实际制作输入的独立对象和判断 |
| RESULT_UNKNOWN | 无法确认执行结果，先核查原请求 |
| core-lock | 项目固定核心提交和受管文件清单摘要 |

## 已采用的关键设计决策

| 决策 | 为什么这样做 | 必须接受的约束 |
| --- | --- | --- |
| 模块化单体与单工作器 | 统一事务、减少重复状态与运行组件 | 后台吞吐受并发上限约束 |
| 对象与修订分开 | 保存创作历史，允许草稿和采用并存 | 每次引用必须明确版本 |
| 关系化身份与 JSONB 正文 | 保持引用可约束，同时容纳丰富内容 | 跨对象关系不能随意内嵌绕过约束 |
| 精确依赖失效 | 修改影响范围与实际输入一致 | 新功能须正确登记依赖用途 |
| AI 预览与正式判断分开 | 人保持裁决权，版本过期可被拒绝 | 建议必须再核对后应用 |
| 固定提交、自包含发布 | 本机与 VPS 可复现并可恢复 | 未提交源码不进入部署 |
| 核心手册与运行时实例映射 | 各项目继承同一说明，实例事实随创作变化 | 通用正文禁止混入真实故事内容 |

## 已知限制

- Schema 当前为 1；部署拒绝不兼容版本，不自动迁移任意旧数据库。
- 单工作器并发为 1，不提供水平扩展调度的承诺。
- 外部模型和制作程序需要宿主显式配置及本轮授权。
- 覆盖检查可以发现类型、表、接口族和引用漂移，不能替代逐章人工核对语义。
- 状态与关系图反映登记事实；不推断听音、看图、法律核验或正式创作范围。
