# 前台业务编号

系统管理的“编号前缀”是只读说明页。它与 `GET /api/business-codes` 共用 `review_desk/business_codes.py` 的类型、前缀、示例与范围，没有手工修改编号入口。

E、S 在同一准确剧本版本内唯一：E 按该版本完整集序从 E01 开始，S 按完整集场顺序从 S001 连续编号，跨集不重置。不同剧本版本各自起号。编号读取不可变剧本版本所引用的准确集修订，不从当前筛选结果、标题或集对象的最新修订推算；未归入完整剧本版本的集不分配 E/S。内嵌场仍由准确集对象身份与场 ID 共同定位。

SH 与 EN、ST、M 等对象编号在整个实例内唯一，不随剧本版本、集、场或排序重新起号。正文、评论、稳定 ID、原有顺序和历史链接不改写。

资料、剧本与故事结构不显示或新分配简写编号；旧 D/B 分配只作为历史恢复占号保留，不进入界面清单。其他前台对象包括实体、状态、素材、实体关系、旧制作设定审阅对象、评论、决定、组合和交付物。后台调用、依赖边、事件、配置表和输入锁不另加展示编号。

`business_codes` 保存其他对象从 object_id 到大写前缀与正整数的分配。首次导入按原登记时间与稳定身份排列分配一次；新增按前缀现有最大号递增。分配记录不随对象删除而回收，不因排序、筛选、刷新或历史访问重新编号。E/S 在读取时从准确剧本版本生成，编号清单同时提供剧本身份、剧本修订和集修订以区分范围；旧的跨版本 E/S 分配若已存在，仍可导出恢复，但不用于展示或继续分配。明确证明共用身份的素材显示规范素材编号，旧别名仍保留独立身份及原版号映射。

素材版本使用 M / MV 加既有局部版号。`business_candidates` 按素材身份、版本和候选稳定身份保存局部 MC 序号，候选元数据补全不改变编号；下一候选递增。详情显示完整 M / MV / MC 上下文，选择按钮严格只写“候选N”。参考卡的 V/C 也使用这两个局部序号，并分别说明选择归属；它们不是素材总数。评论由 `business_comments` 保存全局 C 序号，编辑、关闭、重开与圈选位置不改变它；评论 C 与参考卡候选 C 是不同上下文。

编号仅装饰完整读取对象，不改写准确引用、认可范围、候选身份或内部哈希。Schema 7 输出全部分配及保留编号，空实例恢复保持对应；E/S 由同一份不可变剧本及其准确引用重新得到相同映射。其他编号在旧导出首次恢复后分配一次，并用新导出保存。候选、评论和持久化对象编号的唯一性由数据库约束核对，E/S 按剧本版本分别核对；前缀与类型不匹配的恢复数据拒绝入库。

旧位置转换必须有准确对象映射。无法唯一确定的 `E1-007` 保留为“第1集第7镜”的位置说明，不伪装成全局 SH；场选项必须连同准确集身份读取，不能从标题猜测。

实际实例的完整对象对应和历史位置映射由故事交付包提供。规则变化应先改真实分配与读取，再更新说明，不能只改页面示例。
