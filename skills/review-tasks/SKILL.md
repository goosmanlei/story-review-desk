# 正式任务

任务账本属于当前故事项目；通用实现属于《审阅台》核心。先读项目 README、AGENTS、STATE，使用项目根的 `npm run tasks -- help` 获取命令及 JSON 契约。源码 worktree 只隔离代码，所有任务命令显式指向同一项目根。不要手写账本或把会话历史当作任务状态。

## 发布

和用户当场澄清目标、范围、交付物、验收标准及授权边界。充分明确的发布指令直接入队，不再要求一次形式确认。需要调查的技术原因可以属于任务内容。

未澄清完成前，不生成任务编号、请求文件、草稿、审计事件或待整理记录。结束讨论仍不成熟的想法直接丢弃，不跨会话恢复。没有“先记下来”模式。普通讨论不自动成为正式任务。

澄清完成后调用 `publish --file -`，保留用户原话和澄清后的要求，`clarified:true` 只表示已实际澄清。SYSTEM 先改核心再验证项目继承，CREATIVE 只操作绑定故事，明确引用对象与修订；发布任务不构成正式采用或真实生成的泛化授权。回读正式编号和要求后向用户确认已入案。

默认优先级 2，0 最高；只根据用户明确优先级或已证实的依赖调整。合并/拆解用 CLI 原子操作，不删除原案、不扩大范围。变更中的任务先完成安全检查点，不改写当前目标。

## 执行

用户启动一次后，在当前会话持续执行，不启动额外模型进程或无人值守调度。

1. 读取 `status`、`list` 和项目运行事实。启动 `npm run tasks -- run`，保留该前台工具进程及返回的 runId。已有执行者时不要接管或删除锁，仍可发布和审计。
2. 调用 `next --file -`。CURRENT_TASK 继续当前任务；RECOVERY_REQUIRED 先读任务检查点，现场核查原进程、工作区、版本和每个原操作编号，然后用 `resume` 保存核查结论。不能证明的结果写 RESULT_UNKNOWN 并阻塞，不能自动重新调用。
3. 按任务验收标准执行。系统代码在核心的隔离工作区维护；共享合并、提交和部署使用 `tasks guard --run RUN_ID --task TASK_ID --core -- COMMAND`。其他外部命令也通过 guard 登记；构建、测试和部署再套用项目既有 process 受管执行器。`guard` 不替代业务 API 的版本校验及精确授权。
4. 每个阶段写 checkpoint：已完成、下一步、输入版本、成果引用、验证结论、原操作编号。不可逆或可能结果未知的操作，先登记 PENDING 再执行，完成后登记可核查证据。检查点继承全部操作记录，不能丢弃未决编号。事件中不写密钥、机器绝对路径、Codex 会话标识或完整工具日志。
5. 阶段之间 heartbeat；租约为 10 分钟，guard 中自动续租。资格过期即停止新写入并核查恢复，不能沿用旧 runId。长时间推理前先保存检查点；工具长命令使用 guard。
6. 当前任务完成或阻塞后回到 next，在安全边界领取后来发布的任务。没有可执行项时报告剩余阻塞并 stop；不忙轮询、不把本次未完成说成完成。用户停止时保存检查点，再 stop。异常中断保留任务、原操作及受管恢复输入。

续办不依赖旧对话。恢复核查尚有未知外部结果时，resume 将任务置为 BLOCKED；继续查询原结果，用 checkpoint 保存核查后，再 transition READY 入队。正式任务的新障碍不能导致直接丢弃任务。

## 完成与审计

按每项 acceptanceCriteria 保存逐项证据，结果包含简洁结论、成果引用和清理证明。SYSTEM 分别核实测试、核心/私库提交推送、本地部署、可达 VPS 和清理；未知或跳过如实记录。CREATIVE 的完成以约定交付物为准，不替代用户正式采用。需要人的验收时使用 WAITING_REVIEW。

先通过已有 cleanup:finish、cleanup:check、cleanup:complete 完成过程收尾，再记录 DONE。源码与必要私库内容按项目规则提交推送；任务最终事件可在收尾提交中保存，结果不自引用该提交 SHA。已完成/取消/合并任务只读，新范围重新澄清发布。

审计从 CLI 读权威事件，不凭 Markdown 视图或记忆猜测。可按任务、状态、类型、时间窗口、operationId 查询；使用明确窗口，默认北京时间，展示发布时间、首次开始、完成时间、当前状态、已完成步骤、剩余事项、阻塞、成果和合并拆解关系。不编造完成百分比。任务账本及最终结果长期保留，临时日志仍按过程清理规则处理。

任务记录随私库保存；执行资格、机器参数及会话信息仅在 runtime。复制、导入或部署不自动执行任务，不恢复历史创作或旧授权。
